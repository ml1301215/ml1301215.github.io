    Useful Linux Server Tools

    ← Learning

    Compiled from tools discovered while working on Linux servers. Some are built in; others need to be installed. Listed in order of how frequently I use them.

    1. tmux (Install First, Highest Priority)

    When an SSH connection drops, all running processes in that terminal get killed. tmux keeps your work running after a disconnect, and you can resume seamlessly the next time you connect.

    # Basic operations
tmux new -s mysession       # create a named session
tmux ls                     # list all sessions
tmux attach -t mysession    # reattach to a session

# Shortcuts (all start with Ctrl+b)
Ctrl+b, d     # detach — leave the session (it keeps running in the background)
Ctrl+b, c     # create a new window
Ctrl+b, n     # next window
Ctrl+b, p     # previous window
Ctrl+b, <num> # switch to the numbered window
Ctrl+b, "     # split current pane horizontally
Ctrl+b, %     # split current pane vertically
Ctrl+b, arrow # switch between panes

    A practical workflow: open one tmux session with three windows — one running the training script, one monitoring the GPU, one tailing the log. The training continues after you disconnect; come back and attach.

    2. htop (Process and Resource Monitor)

    More intuitive than the built-in top. Shows per-CPU-core usage, memory, swap, and a process tree.

    sudo apt-get install htop    # install
htop                         # run

# Inside htop:
F5   # toggle tree view (shows parent-child process relationships)
F6   # sort by a field
F9   # kill the selected process
/    # search by process name

    When CPU memory suddenly spikes during training, htop quickly pinpoints which process is responsible.

    3. nvidia-smi (GPU Monitoring)

    Built into the NVIDIA driver — the most basic GPU monitoring tool.

    nvidia-smi                     # one-shot snapshot
watch -n 1 nvidia-smi          # refresh every second
nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total \
  --format=csv -l 1            # show only key metrics, updated every second

    nvtop is a more modern alternative with an htop-style interface; install it with sudo apt install nvtop for more visual monitoring.

    4. nohup and screen (Background Execution)

    If you do not want to use tmux, nohup lets a process continue running after you log out:

    nohup python train.py > train.log 2>&1 &
# redirects output to train.log; & sends it to the background
# the process ID is printed — keep it in case you need to kill it later

    screen is similar to tmux but simpler:

    screen -S train          # create a session
screen -ls               # list sessions
screen -r train          # reattach
Ctrl+a, d                # detach

    tmux has more features (multiple windows, split panes), so prefer it. Use nohup for quickly launching a background task that needs no interaction.

    5. rsync and scp (File Transfer)

    # scp: simple file transfer
scp local_file.txt user@server:/remote/path/
scp -r local_dir/ user@server:/remote/path/    # directory

# rsync: incremental sync, better for large file sets
rsync -avz local_dir/ user@server:/remote/path/
# -a: preserve permissions, timestamps, and other metadata
# -v: verbose output
# -z: compress during transfer
rsync --progress -avz model_weights/ server:/data/weights/

    When transferring model weights (tens of GB), rsync is much faster than scp because it only transfers changed parts, and it handles resume-on-failure reliably.

    6. df and du (Disk Usage)

    df -h             # show remaining space per partition (-h for human-readable sizes)
du -sh /path/*    # show size of each subdirectory under a path
du -sh .          # show total size of the current directory

# find the directories using the most space
du -h --max-depth=1 /data | sort -hr | head -20

    A full disk during training causes a crash with no clear error message. Running df -h periodically is a good habit.

    7. tail and grep (Log Viewing)

    tail -f train.log             # follow the end of a log file in real time
tail -n 100 train.log         # show the last 100 lines
grep "loss" train.log         # filter lines containing "loss"
grep -n "Error" train.log     # show line numbers
tail -f train.log | grep --line-buffered "loss"  # real-time filtered tail

    Training logs are usually long. Filtering with grep is the fastest way to find what you need.

    8. A Few Easily Overlooked but Useful Commands

    free -h               # memory usage (total, used, available, swap)
lscpu                 # CPU info (core count, architecture)
which python          # check which Python is currently active
pip show torch        # show a package's version and install location
ps aux | grep train   # find running training processes
kill -9 PID           # force-kill a process (get PID from ps or htop)
history | grep conda  # search command history

    9. Aliases to Save Time

    Store frequently used long commands as short aliases in ~/.bashrc or ~/.zshrc:

    # add to ~/.bashrc
alias gpu='watch -n 1 nvidia-smi'
alias mem='free -h'
alias py='python3'
alias tl='tail -f'

source ~/.bashrc    # apply the changes

    These aliases load automatically on every login. Typing gpu instantly starts GPU monitoring, saving you from retyping the full command each time.
