    大模型微调笔记：QLoRA + GRPO

    ← Learning

    本笔记基于在成亭科技实习期间（2025年10–12月）对 Qwen3-30B-A3B 进行安全告警分类微调的完整实践过程整理而成。任务目标是将企业 SOC 收到的安全告警自动归类为 critical / high / medium / low / informational 五个等级，辅助安全分析师优先处理高风险事件。微调方案使用 QLoRA 压缩显存占用、GRPO 对齐分类行为，并在 A100 双卡环境下完成训练。

    1. 问题背景：为什么通用 LLM 不够用

    通用大语言模型（如 Qwen3、LLaMA、GPT-4）在大量互联网文本上预训练，具备广泛的语言理解能力。但在企业安全运营中心（SOC）这类高度专业化的场景下，直接使用通用模型往往效果不佳。根本原因并不是模型"不知道"安全知识——大多数主流模型对 CVE、MITRE ATT&CK 框架、常见攻击手法都有一定了解。问题在于分布偏移（distribution mismatch）：模型在训练时从未见过企业内部的告警格式、日志字段命名约定、业务上下文，以及该企业特有的资产重要性定义。

    更根本的挑战是损失不对称性（asymmetric loss）。在通用分类任务中，假阳性和假阴性的代价往往相近，可以用整体精度作为优化目标。但在 SOC 场景中：

    • 漏报 critical/high 告警（假阴性）：可能导致攻击者在网络中长期潜伏、数据泄露或勒索事件，后果极其严重，事后补救成本极高。
    • 误报 critical/high 告警（假阳性）：分析师收到大量误报会产生"告警疲劳"，降低响应速度，但不会直接导致安全事件，危害远小于漏报。

    这种不对称性意味着，即便一个模型在整体 F1 分数上表现不错，只要 critical 告警的召回率不够高，它在生产环境中就是不可用的。标准的监督微调（SFT）以最大化对数似然为目标，将所有错误等同对待，无法天然地编码这种不对称损失。因此，我们需要两件事：

    1. 领域适配（Domain Adaptation）：让模型理解企业内部的告警格式和字段语义——这是分布对齐问题。
    2. 奖励对齐（Reward Alignment）：让模型真正优化"不漏报严重告警"这个业务目标，而不只是拟合标注分布——这是损失函数设计问题。

    QLoRA 解决第一个问题（高效领域适配），GRPO 解决第二个问题（奖励对齐）。两者组合是这个任务的核心技术选型理由。

    任务定义：输入为企业防火墙、IDS、EDR、SIEM 等系统生成的安全告警（包含告警标题、源/目标 IP、端口、协议、原始日志片段、设备类型等字段），输出为五个严重程度等级之一：critical（需立即响应）、high（当天响应）、medium（本周响应）、low（下周排期）、informational（仅记录，无需响应）。告警由 SOC 分析师事后标注，形成训练数据集。数据集规模约 12,000 条，其中 critical 占 4%，high 占 11%，剩余三类各约 20–30%——典型的严重类别稀缺问题。

    2. LoRA：权重更新的低秩分解

    理解 QLoRA 的前提是理解 LoRA（Low-Rank Adaptation）。LoRA 的核心思想是：神经网络在微调过程中，权重矩阵的更新量 ΔW 具有低内在秩（low intrinsic rank），可以用两个小矩阵的乘积来近似表达，从而大幅减少可训练参数量。

    全量微调的显存瓶颈：Qwen3-30B-A3B 有约 300 亿参数。全量微调所需显存：模型参数（fp16，约 60 GB）+ 梯度（同等大小，约 60 GB）+ Adam 优化器状态（两份一阶/二阶动量，约 120 GB）= 约 240 GB。这远超单机多卡的实际能力，在工业界环境中几乎不可行。

    LoRA 的数学形式：对于原始权重矩阵 W ∈ ℝd×k，LoRA 不直接更新 W，而是将增量 ΔW 约束为两个低秩矩阵的乘积：

    W' = W + ΔW = W + A · B
    A ∈ ℝd×r,   B ∈ ℝr×k,   r << min(d, k)

    前向传播时完整计算为：h = W·x + (A·B)·x × (α/r)，其中 α 是缩放超参数。训练时冻结原始权重 W（梯度不通过它传播），只更新小矩阵 A 和 B。推理时可将 ΔW = A·B 合并回 W，推理速度与原始模型完全相同——无额外推理开销。

    参数量对比（以 Qwen3-30B 的注意力投影层为例，d=k=4096，r=8）：

    • 全量微调该层：4096 × 4096 = 16,777,216 个参数
    • LoRA（r=8）该层：8 × (4096 + 4096) = 65,536 个参数
    • 压缩比：约 256:1；总体可训练参数约占模型总参数的 0.14%

    为什么低秩分解能奏效：Aghajanyan et al. (2020) 的实证研究表明，预训练语言模型的"内在维度"很低——在高维参数空间中，有效的优化方向集中在一个远比总维度低的子空间内。微调时的权重更新继承了这一特性：绝大多数对任务有帮助的更新都落在低秩子空间，高秩分量大多是噪声。因此，低秩分解在损失极少有效信息的同时，极大地减少了参数量。

    初始化策略：矩阵 A 用随机高斯初始化，矩阵 B 初始化为全零。这保证训练开始时 ΔW = A·B = 0，即 LoRA 从原始基座模型的行为出发，避免训练初期因随机扰动导致的不稳定。

    # LoRA adds two small matrices A and B alongside the frozen weight W
# Forward pass: h = W·x + (A·B)·x * (alpha/r)
# Only A and B are updated during training; W remains frozen

from peft import LoraConfig

lora_config = LoraConfig(
    r=8,                # rank r: controls LoRA expressiveness
                        # Common choices: 4, 8, 16, 32
                        # r=8 is a safe starting point
                        # Increase to r=16 if the model underfits on your task
                        # Memory scales linearly with r: r*(d+k) params per layer
    lora_alpha=16,      # scaling factor applied as alpha/r in the forward pass
                        # Rule of thumb: set to 2*r initially (here 2*8=16)
                        # Higher alpha = stronger LoRA influence over base weights
                        # Can tune: lower if LoRA is overwhelming base knowledge
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",   # self-attention projections
        "gate_proj", "up_proj", "down_proj",        # MLP (FFN) projections
        # Including all 7 module types gives best coverage for Qwen architecture
        # For simpler tasks, attention-only (first 4) sometimes sufficient
        # FFN projections are important for knowledge/classification tasks
    ],
    lora_dropout=0.05,  # dropout applied to LoRA layers for regularization
                        # 0.05 provides mild regularization
                        # Set to 0 when using unsloth (custom kernel assumes no dropout)
    bias="none",        # whether to train bias terms alongside LoRA weights
                        # "none": don't train biases (most common, safest)
                        # "all": train all biases (marginal gain, more params)
                        # "lora_only": train biases only in LoRA layers
    task_type="CAUSAL_LM",  # task type for PEFT model wrapping
                             # CAUSAL_LM = decoder-only autoregressive model
)

    哪些模块应该加 LoRA：原则是覆盖模型中参数量最集中、对任务最相关的投影矩阵。对于大多数 Transformer 解码器（Qwen、LLaMA、Mistral 等），推荐覆盖所有注意力投影（q/k/v/o）和 FFN 投影（gate/up/down）。对于纯分类或格式迁移类任务，有时注意力层已经足够；对于需要改变模型知识或推理方式的任务，FFN 层不可省略。

    3. QLoRA：4-bit 量化 + LoRA

    QLoRA（Quantized LoRA，Dettmers et al. 2023）在 LoRA 的基础上引入 4-bit 量化，进一步将模型的显存占用从 fp16 的 2 字节/参数压缩到约 0.5 字节/参数。对于 30B 参数的模型：

    • fp16 全量存储：30B × 2 字节 = 60 GB
    • 4-bit 量化存储：30B × 0.5 字节 = 15 GB
    • 节省约 75%，使单张 A100 (80 GB) 可以容纳基座模型 + LoRA 适配器 + 优化器状态

    NF4（NormalFloat4）量化：QLoRA 使用 NF4 数据类型，而不是普通的 INT4。关键区别在于：神经网络权重在预训练后近似服从零均值正态分布。NF4 针对这种分布设计了非均匀量化区间，使得每个 4-bit 值对应的权重范围与权重分布的分位数对齐，理论上是正态分布权重的信息论最优 4-bit 量化方案，比均匀量化损失更少精度。

    双重量化（Double Quantization）：量化过程本身需要存储量化常数（每个量化块的缩放因子），这些常数通常用 fp32 表示，占用额外显存。双重量化将这些量化常数再次量化（fp32 → fp8 或 fp4），进一步减少显存开销。对于 30B 模型，双重量化可额外节省约 3–4 GB。

    分页优化器（Paged Optimizers）：GRPO 训练过程中，优化器状态（Adam 的一阶和二阶动量，各占 trainable_params × 4 字节）会在某些 step 出现显存峰值。分页优化器（paged_adamw_32bit）通过 NVIDIA 统一内存机制，在 GPU 显存不足时自动将优化器状态 offload 到 CPU 内存，避免 OOM，代价是偶发的 CPU-GPU 数据传输延迟。

    计算精度与存储精度分离：量化只影响模型权重的存储格式。实际的矩阵乘法在计算时会将权重反量化为 bf16 或 fp16 进行计算，保持数值精度。这是"近似存储，精确计算"的权衡——存储节省显著，计算精度损失极小。

    import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# ── Step 1: Configure 4-bit quantization ──────────────────────────────────────
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,                      # enable 4-bit loading via bitsandbytes
    bnb_4bit_quant_type="nf4",              # NormalFloat4: optimal for normally-
                                             # distributed weights (beats int4)
    bnb_4bit_compute_dtype=torch.bfloat16, # compute in bf16 for numerical stability
                                             # bf16 preferred over fp16 on Ampere+ GPUs
                                             # (better dynamic range, avoids overflow)
    bnb_4bit_use_double_quant=True,         # quantize the quantization constants too
                                             # saves ~3-4 GB extra on 30B models
)

# ── Step 2: Load model in 4-bit ───────────────────────────────────────────────
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen3-30B-A3B",
    quantization_config=bnb_config,
    device_map="auto",          # distribute layers across available GPUs automatically
    trust_remote_code=True,     # required for Qwen custom model code
)
tokenizer = AutoTokenizer.from_pretrained(
    "Qwen/Qwen3-30B-A3B",
    trust_remote_code=True,
)

# ── Step 3: Prepare model for k-bit training ──────────────────────────────────
# This does two things:
# 1. Casts all LayerNorm layers to fp32 (critical: 4-bit LayerNorms are numerically
#    unstable; fp32 LayerNorms are needed for stable gradient flow)
# 2. Enables gradient checkpointing (recompute activations during backward pass
#    instead of storing them all; reduces activation memory at cost of ~30% more compute)
model = prepare_model_for_kbit_training(model)

# ── Step 4: Apply LoRA ────────────────────────────────────────────────────────
lora_config = LoraConfig(
    r=8, lora_alpha=16,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Output: trainable params: 41,943,040 || all params: 30,143,561,728 || trainable%: 0.14%
# Only 0.14% of parameters are updated — this is why QLoRA fits on a single A100

    QLoRA 的代价：4-bit 量化会引入轻微的量化误差。在分类任务上，我们的实验结果显示，QLoRA（4-bit）与 fp16 LoRA 的分类 F1 差距小于 1pp，在实际应用中可以忽略不计。量化对生成任务（如摘要、对话）的影响可能稍大，但对判别性较强的分类任务几乎无明显影响。

    4. SFT、DPO、PPO、GRPO 横向对比

    在决定使用 GRPO 之前，我们系统评估了四种主流的大模型对齐/微调方法。每种方法针对不同的训练信号和应用场景设计，理解它们的优劣势有助于为特定任务选择合适的方法。

    SFT（监督微调，Supervised Fine-Tuning）：最基础的方法。给定一批（输入, 正确输出）对，最大化模型对正确输出的对数似然。优点：实现简单，收敛速度快，数据格式直觉清晰。缺点：目标函数与业务指标脱节——SFT 优化的是"模型输出与标注文本的字面相似度"，而非"分类是否正确"。更重要的是，SFT 无法编码非对称损失：它将 critical 误判为 informational 与将 medium 误判为 low 等同对待，而前者的实际代价远高于后者。此外，SFT 只能拟合训练集分布，对标注覆盖不足的 critical 类别帮助有限。

    DPO（直接偏好优化，Direct Preference Optimization）：使用偏好对（chosen 优于 rejected）来优化，无需训练独立的 Reward 模型。相比 PPO，DPO 更稳定、实现更简单。缺点：需要成对的标注数据（对同一输入有"好答案"和"坏答案"的对比），数据构造成本较高；偏好对的质量对结果影响极大；难以精确编码连续的、非对称的奖励信号——DPO 只知道 A 比 B 好，但不知道好多少，也无法轻易表达"某种错误比另一种错误坏 6 倍"这样的量化约束。

    PPO（近端策略优化，Proximal Policy Optimization）：完整的强化学习方法。包含 Policy 网络（被训练的 LLM）、Reward 模型（评分器）和 Critic/Value 网络（估计基线）。功能最强大，能编码任意形式的奖励信号。缺点：需要同时维护两个大模型（Policy + Critic），显存占用是单模型的 2 倍以上；Value 网络的训练不稳定，容易出现奖励黑客（reward hacking）；超参数多，调参困难；对于 30B 级别的模型，双 A100 环境下几乎无法运行完整 PPO。

    GRPO（组相对策略优化，Group Relative Policy Optimization）：PPO 的改进变体，专为 LLM 微调设计，由 DeepSeek 团队提出。核心创新：用"组内相对奖励归一化"代替 Critic 网络提供的基线——对同一 prompt 生成 G 个候选输出，将各输出的奖励减去组内均值再除以标准差，得到归一化优势。这样完全去掉了 Value 网络，显存需求降低约一半，训练更稳定。

    选择 GRPO 的具体理由：

    • 无需成对标注数据（只需单条带标签的告警，即可定义奖励）
    • 自定义奖励函数直接编码不对称损失，无需近似
    • 无 Critic 网络，双 A100 环境可运行 30B 级别模型
    • 组内归一化使奖励量纲自适应，无需精心校准奖励的绝对值
    • TRL 库（Hugging Face）提供了生产级 GRPOTrainer 实现，接入成本低
    方法 数据需求 显存需求 自定义奖励 稳定性 推荐场景
    SFT （输入, 输出）对 低 无 高 格式迁移、初始对齐
    DPO 偏好对 中 间接 高 有质量偏好对的对话对齐
    PPO 带奖励的样本 极高（2×） 完全 低 需要复杂奖励且资源充足
    GRPO 带奖励的样本 中（无Critic） 完全 中高 自定义奖励 + 资源受限场景

    5. GRPO 原理

    GRPO（Group Relative Policy Optimization）的核心思想是用"组内相对比较"代替 Critic 网络提供的学习基线，从而在保留 RL 对齐能力的同时，大幅降低计算开销。

    标准 PPO 中的基线问题：策略梯度方法通过最大化期望奖励 E[r(y|x)] 来更新策略参数。直接用奖励作为梯度信号方差极高（不同 prompt 的奖励量纲不同，难以比较），因此 PPO 引入 Value 网络 V(x) 作为基线，将梯度信号替换为优势 A(y,x) = r(y,x) - V(x)。但训练 V(x) 本身需要一个与 Policy 同量级的网络，代价巨大。

    GRPO 的优势估计：对每个 prompt x，采样 G 个候选回答 {y1, ..., yG}，分别计算奖励 {r1, ..., rG}，然后用组内统计量归一化：

    Âi = (ri − mean(r1, ..., rG)) / std(r1, ..., rG)

    组内均值作为自适应基线，组内标准差作为归一化因子。这样，Âi 的含义是：在同一 prompt 的 G 个候选中，第 i 个回答相对于平均水平有多好（以标准差为单位）。

    策略更新目标函数：类似 PPO，使用 clipped surrogate 目标防止策略更新过大：

    LGRPO(θ) = E[ min( rt(θ) ċ Âi,  clip(rt(θ), 1−ε, 1+ε) ċ Âi ) ]

    其中 rt(θ) = πθ(yi|x) / πold(yi|x) 是新旧策略的概率比，ε 是裁剪范围（通常 0.1–0.2），防止策略在单步内更新过多。

    为什么组内归一化是有效基线：Critic 网络的作用是估计"对于 prompt x，期望获得的平均奖励是多少"，以此提供比较基线。对于同一个 prompt x 生成的 G 个回答，它们共享同一个 prompt 的所有上下文因素——只有回答本身的质量差异才导致奖励差异。因此，组内均值天然地近似了 V(x)，且无需任何训练，只需采样即可获得。组内 G 越大，这个近似越准确，梯度方差越低，但计算成本也线性增长。

    KL 散度正则化：为防止策略偏离参考模型（原始基座模型）过远，GRPO 通常在目标函数中加入 KL 惩罚项：L = LGRPO − β ċ KL(πθ || πref)，β 控制正则化强度。这防止模型在追求高奖励时产生退化行为（如输出固定格式套语以稳定获得格式奖励，但丧失语言能力）。

    计算图：一个 GRPO 训练 step 的流程如下：

    1. 从训练集采样一批 prompts {x1, ..., xB}
    2. 对每个 prompt 用当前策略生成 G 个候选回答（共 B×G 个序列）
    3. 对所有 B×G 个回答调用 Reward 函数，得到奖励矩阵 R ∈ ℝB×G
    4. 按行归一化（每个 prompt 独立归一化），得到优势矩阵 Â
    5. 用 clipped surrogate 损失对策略参数做一步梯度更新
    6. 更新参考概率（old policy），准备下一步

    6. Reward 函数设计

    Reward 函数是 GRPO 微调中最关键的设计决策。它是人类对"什么是好的输出"的知识的编码，直接决定模型最终的行为倾向。设计原则：

    1. 编码领域知识：奖励信号应反映任务的真实评价标准，而不是代理指标（如输出长度）。
    2. 显式处理不对称代价：对于代价不对称的错误类型，奖励值的差异应与实际代价差异成正比。
    3. 防御性解析：模型输出是自然语言，可能包含各种格式变体。奖励函数必须能可靠地从输出中提取关键信息，而不是因格式问题将所有格式异常都判为最低奖励。
    4. 奖励量纲校准：奖励绝对值过大或过小都会导致梯度问题。通常将正确奖励设为 +1.0，不同严重程度的错误奖励设为 -0.5 到 -3.0 的范围内。

    安全告警分类的不对称代价矩阵：

    错误类型 例子 实际代价 奖励值
    正确 critical → critical 无 +1.0
    严重低估（2级+） critical → medium/low/info 极高（漏报严重威胁） -3.0
    轻微低估（1级） critical → high, high → medium 较高（优先级降低） -1.5
    严重高估（2级+） info → high/critical 低（增加噪声） -0.5
    相邻错误（1级） medium → high, low → medium 较低（可接受偏差） -0.8
    格式错误 无法解析输出 中等（完全不可用） -1.0

                             # but G× more GPU memory during generation phase
                             # G=8 is a good default; G=4 if memory-constrained
                             # G=16 gave marginal improvement but required halving batch size

                             # important to not cut off thinking tokens if using CoT
    temperature=0.9,         # sampling temperature for generating G candidates
                             # higher temp → more diverse candidates → better gradient signal
                             # too high → incoherent outputs that all get bad rewards
    top_p=0.95,              # nucleus sampling; standard value

    # ── Optimization ──────────────────────────────────────────────────────────
    learning_rate=5e-6,             # low LR critical for RL stability
                                     # SFT typically uses 1e-4 to 2e-4; RL is noisier
                                     # policy gradient updates are high-variance;
                                     # too-high LR causes reward collapse

    监控训练过程的关键指标：

    • reward/mean：组内平均奖励，应在训练初期上升然后趋于稳定（通常稳定在 0.5–0.8 左右）。若奖励持续下降或剧烈震荡，检查 learning_rate 和 kl_coef。
    • reward/std：组内奖励标准差，应保持一定值（不为零）。若接近零，说明所有生成都趋同，梯度信号消失——尝试增大 temperature。
    • kl：与参考模型的 KL 散度，应缓慢上升并在合理范围内（0.1–1.0）稳定。若飙升，增大 kl_coef。
    • policy_loss：策略损失，正常应缓慢降低并最终稳定。

    8. unsloth 加速

    unsloth 是专为 QLoRA/LoRA 训练优化的加速库，通过手写 CUDA kernel 和优化的 Flash Attention 实现，在 A100 上典型提速约 2×（官方在多个基准上报告 1.5–2.5× 加速）。它提供了与 transformers + peft 完全兼容的 API，可以视为"drop-in replacement"——几乎不需要修改训练代码。

    unsloth 的核心优化：

    • 手写 LoRA CUDA kernel：标准 PEFT 的 LoRA 前向/反向传播在 PyTorch 层面实现，有额外的 Python overhead 和 kernel launch 开销。unsloth 将 A·B 的计算与基础权重 W 的矩阵乘法融合为单一 CUDA kernel，减少显存往返次数。
    • Flash Attention 2 集成：自动使用 Flash Attention 2 的分块计算，将注意力计算的显存从 O(n²) 降到 O(n)，对长序列训练尤为重要。
    • 自定义梯度检查点：unsloth 的梯度检查点实现比 transformers 默认版本更激进，在重计算粒度上做了针对 LoRA 的优化，减少不必要的重计算。
    from unsloth import FastLanguageModel

# ── Drop-in replacement for from_pretrained + get_peft_model ──────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen3-30B-A3B",
    max_seq_length=2048,    # maximum sequence length; affects memory allocation
                             # set to actual max(input + output) in your dataset
    dtype=None,              # None = auto-detect
                             # will use bfloat16 on Ampere+ (A100, RTX 3090+)
                             # falls back to float16 on older GPUs
    load_in_4bit=True,       # enable 4-bit NF4 quantization (same as BitsAndBytes)
)

# ── Apply LoRA with unsloth-specific settings ──────────────────────────────────
model = FastLanguageModel.get_peft_model(
    model,
    r=8,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_alpha=16,
    lora_dropout=0,                         # IMPORTANT: must be 0 with unsloth
                                             # unsloth's custom kernel does not support
                                             # dropout in the LoRA computation path
                                             # (standard peft: set to 0.05)
    bias="none",
    use_gradient_checkpointing="unsloth",   # use unsloth's custom gradient checkpointing
                                             # more memory-efficient than standard
                                             # "True" also works but is slower
    random_state=42,
    use_rslora=False,       # RSLoRA: rank-stabilized LoRA (scales by 1/sqrt(r))
                             # useful when r is large (>=32); off by default
    loftq_config=None,      # LoFTQ: quantization-aware LoRA initialization
                             # can improve convergence on highly quantized models
                             # set to LoftQConfig() if NF4 precision is insufficient
)

    9. 超参数调参指南

    以下是对每个关键超参数的系统性指南，包括它控制的内容、典型取值范围、以及基于实验经验的调参法则。

    LoRA 架构参数

    r（秩）：控制 LoRA 的表达能力。r 越大，可学习的更新维度越多，但可训练参数量以 O(r) 增长（具体为 r×(d+k) per layer）。

    • 典型范围：4, 8, 16, 32（超过 64 通常无明显收益）
    • 起点：r=8。若训练 loss 快速收敛但验证集性能差（欠拟合），增大到 r=16 或 r=32
    • 若任务非常简单（如格式转换），r=4 已足够；若需要显著改变模型的知识或推理策略，考虑 r=32
    • 注意：更大的 r 不一定更好，超过某个阈值后性能趋于平稳而显存持续增加

    lora_alpha（缩放因子）：控制 LoRA 更新相对于基座权重的影响强度，前向传播的缩放系数为 alpha/r。

    • 起点：设为 2×r（即 r=8 → alpha=16）
    • 若 LoRA 没有足够影响力（模型行为改变不明显），增大 alpha 或减小 r
    • 若训练不稳定（loss 震荡），减小 alpha 或增大 r（降低缩放比）
    • RSLoRA（use_rslora=True）将缩放改为 alpha/sqrt(r)，对大 r 更稳定

    target_modules：决定哪些权重矩阵接受 LoRA 适配。

    • 最全覆盖（推荐）：注意力投影（q/k/v/o）+ FFN 投影（gate/up/down），共 7 类
    • 最小覆盖：仅 q_proj + v_proj（参数量最少，适合极度显存受限场景）
    • 经验法则：分类和知识密集型任务需要 FFN 层；纯格式迁移任务注意力层可能足够

    GRPO 训练参数

    learning_rate：RL 微调最敏感的超参数之一。

    • SFT 典型范围：1e-4 到 2e-4
    • GRPO 推荐范围：1e-6 到 1e-5（比 SFT 低 1–2 个数量级）
    • 原因：策略梯度更新噪声大，大 LR 会导致策略剧烈抖动，产生"奖励崩溃"（reward collapse）——模型学会了某个能稳定拿到奖励的简并策略，而不是真正的分类能力
    • 起点：5e-6；若奖励曲线震荡大，减小到 2e-6；若奖励上升过慢，增大到 1e-5

    num_generations（G）：每个 prompt 生成的候选数量。

    • 典型范围：4 到 16
    • G=8 是我们实验中的最优平衡点：梯度质量与显存/速度的最佳折中
    • G=4：训练更快，但优势估计噪声更大，需要更多 epoch 收敛
    • G=16：梯度更准确，但需要减少 per_device_train_batch_size 到 1
    • 显存影响：G 个候选序列同时驻留显存，G 增大 1 相当于 batch 增大 1

    gradient_checkpointing：激活显存与计算速度的权衡。

    • 30B+ 模型必须启用；20B 以下可选（启用可以增大 batch size 或序列长度）
    • 典型代价：增加约 30% 计算时间，换取约 8–10× 激活显存节省
    • 用 unsloth：设为 "unsloth" 而不是 True，效果更好

    per_device_train_batch_size：单卡单步处理的 prompt 数量。

    • 起点：2（30B 模型在单 A100 80GB 上）；若 OOM 减小到 1
    • 用 gradient_accumulation_steps 补偿：effective_batch = batch_size × accum_steps
    • GRPO 的实际计算量为 effective_batch × G，确保这个乘积在 32–128 之间

    warmup_ratio：预热步数占总步数的比例。

    • RL 训练中比 SFT 更重要：预热阶段用极小 LR 让策略先"热身"，避免初期大梯度破坏基座能力
    • 推荐：0.05 到 0.1（5%–10% 的步数用于预热）

    kl_coef（KL 系数）：控制策略与参考模型的偏离惩罚强度。

    • 典型范围：0.001 到 0.1
    • 太小：模型可能学会奖励黑客（用奇特格式"套"奖励）
    • 太大：策略更新受到强约束，难以偏离基座模型，学习效率低
    • 起点：0.01；监控 KL 散度值，保持在 0.1–1.0 范围内

    10. OOM 调试流程

    显存不足（Out of Memory）是 30B 级别模型训练中最常见的问题。有效的 OOM 调试需要系统化，而不是随机尝试降低各种参数。以下是我们在实践中形成的调试流程。

    第一步：定位 OOM 发生在哪个阶段

    • 数据加载阶段：极少数情况，通常是 tokenization 时序列过长。检查 max_seq_length。
    • 前向传播（forward）：模型参数 + 激活占用超限。症状：第一个 training step 就 OOM。
    • 反向传播（backward）：梯度 + 激活占用超限。症状：forward 正常，backward OOM。
    • 优化器步骤（optimizer step）：优化器状态骤然加载。症状：几个 step 后 OOM。使用 paged 优化器可缓解。
    • GRPO 生成阶段：G × batch_size 个序列同时生成。症状：reward 计算前 OOM。

    第二步：按优先级逐一尝试以下缓解措施

    1. 减小 batch size 到 1：最直接的显存缩减手段。用 gradient_accumulation_steps 维持有效 batch 大小。
    2. 启用 gradient_checkpointing：若尚未启用，立即开启。30B 模型必须。节省激活显存 8–10×。
    3. 缩短 max_seq_length：注意力的 KV cache 随序列长度平方增长（Flash Attention 后线性，但常数项仍大）。分析数据集中的实际最大长度，设置合理上限。
    4. 切换到分页优化器：optim="paged_adamw_32bit"，将优化器状态 offload 到 CPU，减少 GPU 显存峰值。
    5. 减小 num_generations (G)：从 8 减到 4，GRPO 生成阶段的显存减半。梯度质量降低，但通常可接受。
    6. 减小 LoRA rank r：从 8 减到 4，可训练参数减半，对训练显存影响较小，但影响模型能力。
    7. 使用 unsloth：若上述措施仍不够，切换到 unsloth，其自定义 kernel 在相同计算量下使用更少显存。
    8. 多卡分布式训练：使用 DeepSpeed ZeRO-3 将参数、梯度、优化器状态分片到多卡。注意 GRPO 与 ZeRO-3 的兼容性需要验证。

    显存估算（诊断用）：

    组件 估算公式 30B NF4 示例
    基座模型（4-bit） params × 0.5 bytes 30B × 0.5 = 15 GB
    LoRA 参数（bf16） trainable_params × 2 bytes 42M × 2 = 84 MB
    激活（含梯度检查点） batch × seq_len × hidden × layers × 2 bytes / 8 2 × 2048 × 7168 × 80 × 2 / 8 ≈ 7 GB
    优化器状态（Adam） trainable_params × 2 × 4 bytes 42M × 8 = 336 MB
    GRPO 生成缓存 G × batch × seq_len × hidden × 2 bytes 8 × 2 × 128 × 7168 × 2 ≈ 3 GB
    总计（估算） ≈ 26 GB（单 A100 可运行）

    注意这只是近似值；实际占用受 PyTorch 内存碎片化、框架 overhead 等因素影响，通常比估算高 10–20%。建议在正式训练前用 1 个 step 测量实际峰值（torch.cuda.max_memory_allocated()）。

    11. 评估与分析

    为什么不能只看准确率：我们的数据集中 critical 占 4%，informational 占 30%。一个将所有告警预测为 informational 的哑模型准确率可达 30%，但 critical 召回率为 0——在生产环境中完全没有价值。对于类别严重不平衡的分类任务，准确率（accuracy）是一个误导性指标。

    应该关注的指标：

    • 逐类 Precision / Recall / F1：分别报告每个严重级别的精准率和召回率，了解模型在哪些类别上表现最差。
    • Critical 告警召回率：最重要的单一业务指标。目标：在生产环境中不低于 95%（即每 100 个真实 critical 告警，漏报不超过 5 个）。
    • 混淆矩阵：可视化所有类别对之间的混淆模式，识别系统性错误（如模型经常把 high 误判为 medium）。
    • 训练过程中的 Reward 曲线：reward/mean 应稳定上升然后趋于平稳；reward/std 应保持非零（表明组内仍有多样性）。
    • 生成解析成功率：extract_severity 返回 "unknown" 的比例，衡量输出格式的可靠性。
    from sklearn.metrics import classification_report, confusion_matrix
import numpy as np

LABEL_LIST = ["critical", "high", "medium", "low", "informational"]

def evaluate_model(model, tokenizer, eval_dataset, label_list=LABEL_LIST):
    """
    Comprehensive evaluation for the alert severity classification model.
    Returns per-class metrics and highlights the critical recall.
    """
    model.eval()
    predictions = []
    true_labels  = []
    parse_failures = 0

    with torch.no_grad():
        for sample in eval_dataset:
            input_ids = tokenizer(
                sample["prompt"],
                return_tensors="pt",
                truncation=True,
                max_length=1024,
            ).input_ids.cuda()

            output_ids = model.generate(
                input_ids,
                max_new_tokens=64,
                temperature=0.1,        # low temp for deterministic eval
                do_sample=False,        # greedy decoding for reproducibility
            )

            # Decode only the new tokens (not the prompt)
            new_tokens = output_ids[0, input_ids.shape[1]:]
            response = tokenizer.decode(new_tokens, skip_special_tokens=True)

            pred = extract_severity(response)
            if pred == "unknown":
                parse_failures += 1
                pred = "informational"  # conservative fallback for eval

            predictions.append(pred)
            true_labels.append(sample["label"])

    # ── Per-class report ───────────────────────────────────────────────────────
    print("=" * 60)
    print("Per-class Classification Report")
    print("=" * 60)
    print(classification_report(true_labels, predictions, labels=label_list,
                                 digits=3, zero_division=0))

    # ── Confusion matrix ───────────────────────────────────────────────────────
    print("Confusion Matrix (rows=true, cols=predicted):")
    cm = confusion_matrix(true_labels, predictions, labels=label_list)
    print("Labels:", label_list)
    print(cm)

    # ── Most important: critical recall ───────────────────────────────────────
    critical_idx = label_list.index("critical")
    critical_row = cm[critical_idx]
    critical_recall = critical_row[critical_idx] / critical_row.sum() if critical_row.sum() > 0 else 0.0
    critical_false_neg_to_medium_plus = (
        sum(critical_row[label_list.index(l)]
            for l in ["medium", "low", "informational"])
    )

    print("\n" + "=" * 60)
    print("Business-Critical Metrics")
    print("=" * 60)
    print(f"Critical alert recall:        {critical_recall:.3f}  (target: >= 0.95)")
    print(f"Critical → medium/low/info:   {critical_false_neg_to_medium_plus}  (dangerous misses)")
    print(f"Parse failure rate:           {parse_failures / len(predictions):.3f}")

    # ── Severity-weighted error analysis ─────────────────────────────────────
    total_errors = 0
    dangerous_errors = 0  # underestimates by 2+ severity levels
    for i, true_l in enumerate(label_list):
        for j, pred_l in enumerate(label_list):
            if i != j and cm[i, j] > 0:
                true_rank = SEVERITY_RANK[true_l]
                pred_rank = SEVERITY_RANK[pred_l]
                if true_rank - pred_rank >= 2:  # dangerous underestimate
                    dangerous_errors += cm[i, j]
                total_errors += cm[i, j]

    print(f"Dangerous underestimates:     {dangerous_errors} / {total_errors} errors "
          f"({dangerous_errors/total_errors*100:.1f}% of all errors)" if total_errors > 0
          else "Dangerous underestimates:     0")

        "critical_recall": critical_recall,
        "parse_failure_rate": parse_failures / len(predictions),
        "confusion_matrix": cm,

    训练曲线异常的诊断：

    • 奖励迅速达到上限并停止增长：可能是奖励黑客——模型学会了某个能稳定获得高奖励的简单规则（如总是输出 "high"）。检查 reward/std 是否趋近于零，以及每个类别的预测分布是否严重偏斜。
    • 奖励持续震荡不收敛：learning_rate 过大或 kl_coef 过小。先尝试减半 learning_rate。
    • 训练初期奖励突然崩溃：预热步数不够，或 learning_rate 太大导致策略初期过度更新。增大 warmup_ratio 到 0.15。
    • 验证集 critical recall 低但训练奖励高：过拟合或分布偏移。检查训练集 critical 样本是否足够多样；考虑数据增强。

    12. 实验结论

    以下是从成亭科技项目中提炼的核心结论，对未来类似项目具有参考价值。

    结论一：Reward 函数设计 > 基座模型选择

    这是本项目最重要的发现。使用非对称 reward（对漏报严重告警给予重惩）与对称 reward（只区分对/错，代价相同）相比，critical 告警召回率提升约 15 个百分点（从约 0.72 到约 0.87）。而在相同量级的基座模型之间切换（Qwen3-30B-A3B vs 同规模的其他模型）对这个指标的影响约为 3pp。这说明：对于业务目标明确的任务，训练信号的设计质量远比模型本身更重要。"用更好的模型"是诱人但低效的路径；"用更准确的 reward"是高回报的投入。

    结论二：GRPO 训练稳定性良好

    在 lr=5e-6、kl_coef=0.01、G=8 的配置下，GRPO 在 3 个 epoch 内稳定收敛，奖励曲线单调上升后平稳，没有出现奖励崩溃或严重震荡。相比之下，我们在初期尝试 PPO 时，Value 网络的不稳定性导致训练在约 200 step 后发散。GRPO 的去 Critic 设计在这个任务上展示了实质性的稳定性优势。

    结论三：QLoRA 精度损失可忽略

    在相同训练配置下对比 QLoRA（4-bit NF4）与 fp16 LoRA：整体 weighted F1 差距小于 1pp（0.86 vs 0.87），critical recall 差距约 0.5pp。4-bit 量化对分类型任务的精度影响极小，而显存节省（60 GB → 15 GB）是实质性的。这一结论与 Dettmers et al. 的原始论文一致，但现在有了特定任务的实验验证。

    结论四：输出格式的显式约束至关重要

    在 prompt 末尾加入 "Respond with exactly one word: critical, high, medium, low, or informational." 将输出解析成功率从约 73% 提升到约 97%。在格式不确定的情况下，约 27% 的输出无法可靠解析，这些样本会被分配 -1.0 的惩罚奖励，大量污染训练信号。结构化输出约束是提升解析率的最低成本手段。

    结论五：G=8 是组大小的甜点

    系统地测试了 G=4、8、16：

    • G=4：梯度估计噪声较大，需要多约 1 个 epoch 才能达到与 G=8 相当的性能，但每步计算量更少，适合显存极度受限的情况。
    • G=8：最优平衡。在 A100×2 环境下 batch_size=2 时内存使用率约 75%，训练速度与梯度质量的平衡最好。
    • G=16：critical recall 相比 G=8 提升约 1pp，但需要将 batch_size 减小到 1，整体训练时间反而更长。边际收益低于边际成本。

    结论六：阶段性训练策略有效

    我们最终采用了两阶段策略：第一阶段用 SFT 在标注数据上做 1 个 epoch 的初始对齐（让模型先学会正确的输出格式和大致的分类方向），第二阶段再用 GRPO 做奖励对齐。相比直接从基座模型开始 GRPO，SFT 热启动使 GRPO 阶段的收敛速度加快约 30%，且早期训练更稳定（因为初始策略已经能输出格式正确的分类结果，奖励信号质量更高）。

    总结：给类似项目的建议优先级排序

    1. 先把 reward 函数设计做对（不对称代价、防御性解析、奖励量纲）
    2. 用结构化输出 prompt 保证解析成功率
    3. 用 SFT 做初始热启动，再切到 GRPO
    4. 从 G=8、lr=5e-6 开始，不要在超参上过早花时间
    5. 以 critical recall 为核心评估指标，不要被整体 accuracy/F1 迷惑
    6. 在以上都做好之后，再考虑换更大的模型
