    Lean 4 Getting Started: From Competition Math to Mathlib Formalization

    ← Learning

    This guide is aimed at readers with a mathematics background but no prior type-theory experience, compiled from the practical work of formalizing 18 ICCM competition problems.

    1. Why Lean 4

    The four common theorem provers are: Coq (INRIA, OCaml-based), Isabelle/HOL (Cambridge/Munich, ML-family), Agda (Chalmers, dependent types), and Lean 4 (Microsoft Research / Leanprover community, C++ with self-hosted Lean). The comparison below is grounded in what's actually needed to formalize ICCM-style problems, and explains why I went with Lean 4.

    Compared with Coq. Coq has decades of accumulated work but a relatively heavy syntax, and its tactic language Ltac is divorced from the main language, which makes the learning curve steep. The MathComp library is mature but uses a terse naming style, and its coverage of real analysis and combinatorics — both relevant for competition problems — isn't comprehensive. Mathlib4 has surpassed MathComp in breadth, and Lean 4 unifies tactic syntax with the main language so it reads closer to ordinary mathematical writing.

    Compared with Isabelle. Isabelle/HOL has very strong automation (sledgehammer can call out to external SMT/ATP solvers), which is useful for problems that require long algebraic manipulation. But its type system is relatively weak and less expressive than dependent types, and the community is concentrated in European academia with sparse Chinese-language resources. For competition-level work, Lean 4's decide, norm_num, omega, and similar tactics are already enough.

    Compared with Agda. Agda is a research tool at the frontier of dependent-type theory, with the most expressive system, but almost nothing aimed at competition mathematics. Formalizing an elementary number-theory problem in Agda would mean building up a lot of infrastructure from scratch — not a good fit when the goal is "complete the formalization."

    Mathlib4 coverage. As of 2025, Mathlib4 has over 180,000 lemmas, covering elementary number theory, linear algebra, polynomial theory, real and complex analysis, combinatorics, algebraic topology, category theory, and more. For ICCM-level problems, almost all the tools you need exist as off-the-shelf lemmas, so you rarely have to prove something from scratch.

    Active community and continuous development. Lean 4 is led by Leonardo de Moura, Mathlib4 has more than 500 contributors, and new lemmas are merged every week. Discussion happens on Zulip (leanprover.zulipchat.com).

    Fit for ICCM problems. ICCM problems are mostly algebra, number theory, and combinatorics — areas Mathlib4 covers well. Lean 4's tactic language tracks how a proof is written by hand: have for intermediate steps, ring for algebraic identities, linarith for inequalities. The structure of the formal proof maps cleanly onto a paper proof.

    2. Environment Setup

    The following steps work on Windows 10/11, macOS, and major Linux distributions. Linux/macOS is preferable — the Lean 4 toolchain is more mature on those platforms and builds are faster.

    2.1 Install elan (the Lean version manager)

    elan is Lean 4's version manager, similar to Rust's rustup. In a terminal:

    # Linux / macOS
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh

# Windows (PowerShell; install curl first, or use winget)
winget install leanprover.elan
# or download elan-init.exe and run it directly

    Restart the terminal after installation, then run elan --version to verify. elan automatically manages the Lean toolchain version each project uses, so you don't have to switch by hand.

    2.2 Create a New Project

    Use Lake (Lean's build system) to create a new project that depends on Mathlib4:

    lake new myproject math
cd myproject

    The math argument tells Lake to use the math template, which generates a lakefile.toml with a Mathlib4 dependency. You can also write the file by hand:

    import Lake
open Lake DSL

package «myproject» where
  name := "myproject"

require mathlib from git
  "https://github.com/leanprover-community/mathlib4" @ "v4.27.0"

lean_lib «Myproject» where

    The version v4.27.0 pins the Mathlib4 release. Pinning is recommended for reproducibility; when you want to upgrade, change the version here and re-run lake update.

    2.3 Download the Mathlib Cache

    Compiling Mathlib4 from source takes hours, but the community provides a precompiled binary cache (about 1–2 GB). From the project root:

    lake exe cache get

    This downloads the compiled cache matching the current toolchain version. After this, lake build takes a few minutes instead of hours. If your network is slow, consider a mirror or pre-downloading on a machine with better connectivity.

    2.4 VS Code Setup

    In the VS Code marketplace, search for and install lean4 (extension ID: leanprover.lean4). The extension will:

    • Detect lakefile.toml in the project and configure the language server
    • Show a Lean Infoview panel on the right (toggle with Ctrl+Shift+Enter)
    • Update the current proof state in real time as you move the cursor
    • Provide completion, lemma search, and syntax highlighting

    After opening the project, the VS Code status bar shows the Lean server's load state. The first open takes 30 seconds to a couple of minutes for the language server to start. When you move the cursor inside a tactic block following by, the Infoview shows the proof state in this format:

    ⊢ n * (n + 1) % 2 = 0
-- The line above is the goal
-- Hypotheses:
a b : ℤ
h : a + b = 0

    2.5 Verify the Install

    Put the following in Myproject.lean. If the Infoview shows no errors and completion works, the install is good:

    import Mathlib

-- Verify Mathlib is available
#check Nat.add_comm
#eval 2 + 3  -- should output 5

theorem hello_lean : 1 + 1 = 2 := by norm_num

    3. Core Concept: Propositions as Types

    The first step in understanding Lean 4 is accepting the Curry–Howard isomorphism (propositions are types, proofs are programs) as a working idea. It isn't just a philosophical metaphor — it's how Lean 4 is actually implemented.

    3.1 Propositions Are Types

    In Lean 4, every proposition is a type, and a proof of that proposition is a term of that type. Concretely:

    • 1 + 1 = 2 is a type (a proposition type)
    • To supply a proof is to construct a term of that type
    • theorem foo : P := proof_term declares foo as a term of type P

    So "proving a proposition" and "writing a function" are the same activity. Implication P → Q is the function type from P-terms to Q-terms; the universal quantifier ∀ x, P x is a dependent function type; the existential quantifier ∃ x, P x is a dependent pair type.

    -- A proof of P → Q is a function
-- given h : P (a term of type P), return a term of type Q
theorem modus_ponens (P Q : Prop) (hpq : P → Q) (hp : P) : Q :=
  hpq hp  -- direct function application

-- Universal quantification: ∀ n : ℕ, 0 ≤ n
-- equivalent to: a dependent function returning a proof of 0 ≤ n for each n
theorem zero_le_all : ∀ n : ℕ, 0 ≤ n := Nat.zero_le

    3.2 Tactic Mode

    Writing proof terms directly (term-mode proofs) is hard for non-trivial propositions, because you have to keep the entire type structure in your head at once. Lean 4 provides tactic mode, entered with the by keyword, which lets you reduce the goal step by step and only worry about the current state at each step.

    -- Term mode: write the proof term directly
theorem add_comm_example (a b : ℕ) : a + b = b + a :=
  Nat.add_comm a b

-- Tactic mode: enter via the `by` keyword
theorem add_comm_example' (a b : ℕ) : a + b = b + a := by
  exact Nat.add_comm a b  -- exact provides the precise proof term

-- More involved example, showing step-by-step decomposition
theorem example_tactic (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  exact Nat.le_trans h1 h2

    3.3 Reading the Infoview

    In tactic mode, the Infoview is your main navigation tool. Reading it fluently is essential:

    -- Place the cursor after a tactic line; the Infoview shows the state after that line
-- Format:
--
-- case left
-- a b : ℤ
-- h : a > 0
-- ⊢ a + b > b
--
-- Reading:
-- "case left"  — current branch in a constructor/cases split
-- "a b : ℤ"   — variables in scope and their types
-- "h : a > 0"  — hypothesis named h in scope
-- "⊢ a + b > b" — current goal (⊢ is read "turnstile")

-- "No goals" means the proof is finished
theorem simple_example (a b : ℤ) (h : a > 0) : a + b > b := by
  linarith  -- after this, the Infoview shows "No goals"

    When you don't know what to do next, the most useful move is: read the current goal's shape, then pick a tactic that matches that shape. Section 5 walks through tactics by category.

    3.4 The sorry Placeholder

    sorry is Lean 4's universal proof term — it fits any goal, but produces a warning. When working on a complex theorem, sketching the structure with sorry and filling in the pieces gradually is a common workflow. A file containing sorry still type-checks, but lake build emits warnings; it doesn't count as a finished formalization.

    -- Use sorry to sketch the proof
theorem complex_theorem (n : ℕ) : n * (n + 1) % 2 = 0 := by
  sorry  -- to be filled in

-- Fill in step by step
theorem complex_theorem' (n : ℕ) : n * (n + 1) % 2 = 0 := by
  have h : n * (n + 1) = 2 * (n * (n + 1) / 2) := by sorry
  sorry

    4. Basic Syntax

    4.1 Definitions and Inspection

    -- def: define a constant or function
def myNat : ℕ := 42
def double (n : ℕ) : ℕ := 2 * n
def add3 (a b c : ℕ) : ℕ := a + b + c

-- #check: query a type (does not evaluate)
#check myNat         -- myNat : ℕ
#check double        -- double : ℕ → ℕ
#check Nat.add_comm  -- Nat.add_comm : ∀ (n m : ℕ), n + m = m + n

-- #eval: evaluate (runtime computation)
#eval double 21      -- 42
#eval 2 ^ 10         -- 1024
#eval Nat.gcd 12 8   -- 4

    4.2 Function Types

    -- Plain function type: A → B
def f : ℕ → ℕ := fun n => n + 1

-- Multi-argument (curried): A → B → C
def g : ℕ → ℕ → ℕ := fun a b => a * b

-- Dependent type: ∀ (n : ℕ), P n
-- mathematically: "for all n, P n holds"
def h : ∀ (n : ℕ), n + 0 = n := fun n => Nat.add_zero n

-- Anonymous function (lambda)
#check fun (x : ℝ) => x ^ 2   -- ℝ → ℝ
#eval (fun x => x + 1) 5       -- 6

-- Pattern matching
def factorial : ℕ → ℕ
  | 0     => 1
  | n + 1 => (n + 1) * factorial n

#eval factorial 5  -- 120

    4.3 theorem and have / show / exact

    -- theorem: declare a theorem
theorem nat_add_zero (n : ℕ) : n + 0 = n := by
  exact Nat.add_zero n

-- have: introduce an intermediate step (with a local name)
theorem transitivity_example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  have step : a ≤ c := Nat.le_trans h1 h2  -- named "step"
  exact step

-- have without a name (anonymous, accessible as "this")
theorem example_with_have (n : ℕ) : n + n = 2 * n := by
  have : n + n = 2 * n := by ring
  exact this

-- show: rewrite the goal in an equivalent form (useful when definitionally equal)
theorem show_example (n : ℕ) : n * 2 = n + n := by
  show n * 2 = n + n
  ring

-- exact: provide a proof term that exactly matches the goal
theorem exact_example : 1 + 1 = 2 := by
  exact rfl  -- rfl is reflexivity; works for computable equalities

-- from: alias for exact (reads more like English word order)
theorem from_example (h : 1 = 1) : 1 = 1 := by
  exact h

    4.4 Variables and Namespaces

    -- variable: declare a global variable shared by all theorems in the file
variable (n m k : ℕ)
variable (a b c : ℝ)

-- namespace: organize code
namespace MyLemmas

theorem double_add (x : ℤ) : x + x = 2 * x := by ring

end MyLemmas

-- prefix the namespace when using
#check MyLemmas.double_add

-- open: open a namespace (avoid repeating prefixes)
open Nat in
#check succ_pos  -- equivalent to Nat.succ_pos

    5. Tactics

    Tactics are the working tools of Lean 4 proofs. Below they are grouped by function, with definition, use cases, and full code examples for each.

    5.1 Automated Solvers

    ring — proves polynomial equalities in a commutative ring. Normalizes both sides and compares; handles +, −, ×, and powers. Doesn't handle division (use field_simp first on a field).

    -- The classic: difference of squares
example (a b : ℝ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring

-- Expanding a product
example (x y : ℤ) : (x + y) ^ 2 = x ^ 2 + 2 * x * y + y ^ 2 := by ring

-- Verifying an algebraic identity
example (a b c : ℝ) : (a + b + c) ^ 2 = a^2 + b^2 + c^2 + 2*a*b + 2*b*c + 2*a*c := by ring

-- ring fails on ℕ subtraction (ℕ uses truncated subtraction)
-- The following fails on ℕ; convert to ℤ
-- example (a b : ℕ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring  -- fails
example (a b : ℤ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring  -- works

    norm_num — verifies propositions about specific numerical values. Handles size comparisons, divisibility, primality, square roots, and other claims involving concrete numbers.

    -- Numerical equality
example : (2 : ℝ) + 3 = 5 := by norm_num

-- Inequality
example : (7 : ℝ) > 3 := by norm_num

-- Divisibility
example : (6 : ℤ) ∣ 42 := by norm_num

-- Primality
example : Nat.Prime 997 := by norm_num

-- Showing a number is not prime (1001 = 7 × 11 × 13)
example : ¬ Nat.Prime 1001 := by norm_num

-- Fraction arithmetic
example : (1 : ℚ) / 3 + 1 / 6 = 1 / 2 := by norm_num

-- Large-number arithmetic (norm_num uses efficient algorithms)
example : (2 : ℕ) ^ 31 - 1 = 2147483647 := by norm_num

    omega — decision procedure for linear integer/natural-number arithmetic (Presburger arithmetic). Handles equalities and inequalities involving +, −, and constant multiples; doesn't handle multiplication of variables.

    -- Basic linear arithmetic
example (n : ℕ) : n + 1 > n := by omega

-- Divisibility via remainders
example (n : ℕ) (h : n % 2 = 0) : (n + 2) % 2 = 0 := by omega

-- Linear relations among multiple variables
example (a b : ℤ) (h1 : a ≤ b) (h2 : b ≤ a + 3) : b - a ≤ 3 := by omega

-- Bounds on natural numbers
example (n : ℕ) (h : n < 10) : n ≤ 9 := by omega

-- Absolute-value-style inequalities (split cases first if needed, then omega)
example (a b : ℤ) (h : a + b = 0) : a = -b := by omega

    linarith — proves linear inequalities via Farkas' lemma. Unlike omega, linarith works over the reals (and any ordered field) and can combine hypotheses in context.

    -- Transitivity from hypotheses
example (a b c : ℝ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by linarith

-- Combining multiple inequalities
example (x y : ℝ) (h1 : x ≥ 0) (h2 : y ≥ 0) (h3 : x + y = 1) : x ≤ 1 := by linarith

-- Deriving a contradiction
example (a b : ℝ) (h1 : a > b) (h2 : b > a) : False := by linarith

-- Combined with have
example (n : ℝ) (h : n > 2) : n ^ 2 > 4 := by
  have h2 : n > 0 := by linarith
  nlinarith [sq_nonneg (n - 2)]

    nlinarith — a non-linear extension of linarith that handles inequalities involving products. Usually needs hints (non-negative squares) to help the solver.

    -- AM-GM: a² + b² ≥ 2ab
example (a b : ℝ) : a ^ 2 + b ^ 2 ≥ 2 * a * b := by
  nlinarith [sq_nonneg (a - b)]
  -- Hint: (a-b)² ≥ 0; expanding it gives the desired conclusion

-- Inequality involving squares
example (x : ℝ) (h : x > 0) : x + 1 / x ≥ 2 := by
  have h1 : x > 0 := h
  have h2 : (x - 1) ^ 2 ≥ 0 := sq_nonneg _
  nlinarith [mul_pos h1 h1]

-- Multiple hints
example (a b c : ℝ) (ha : a ≥ 0) (hb : b ≥ 0) (hc : c ≥ 0) :
    a * b + b * c + a * c ≤ a ^ 2 + b ^ 2 + c ^ 2 := by
  nlinarith [sq_nonneg (a - b), sq_nonneg (b - c), sq_nonneg (a - c)]

    decide — mechanically verifies decidable propositions (Decidable). Suitable for finite-domain claims, like universal statements over a small range or concrete Prop computations.

    -- Verify a small prime
example : Nat.Prime 7 := by decide

-- Universal over a finite set
example : ∀ n : Fin 5, n.val < 5 := by decide

-- Boolean equality
example : (true && false) = false := by decide

-- Small-range divisibility
example : 3 ∣ 12 := by decide

-- decide can time out on large numbers; native_decide (JIT-compiled) is faster
example : Nat.Prime 65537 := by native_decide

    5.2 Logical Reasoning

    exact h — closes the current goal when a hypothesis or lemma h in context matches it exactly. The most basic tactic.

    example (P : Prop) (h : P) : P := by exact h

-- exact also accepts complex expressions
example (a b : ℕ) (h : a = b) : b = a := by exact h.symm

-- exact with a lemma application
example (n : ℕ) : n ≤ n := by exact Nat.le_refl n

    intro h — given a goal P → Q, introduces P as a hypothesis named h and changes the goal to Q. For a universal goal ∀ x, P x, intro x introduces an arbitrary variable.

    -- Introduce the antecedent of an implication
example (P Q : Prop) : P → P := by
  intro h  -- h : P, goal becomes P
  exact h

-- Introduce multiple variables/hypotheses at once
example (a b c : ℝ) : a ≤ b → b ≤ c → a ≤ c := by
  intro h1 h2
  linarith

-- Introduce a universally quantified variable
example : ∀ (n : ℕ), n + 0 = n := by
  intro n
  exact Nat.add_zero n

-- intro with pattern destructuring
example (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro ⟨hp, hq⟩  -- destructure the conjunction
  exact ⟨hq, hp⟩

    apply h — backward reasoning: if h : A → B (or more generally A₁ → A₂ → ... → B) and the goal is B, apply h changes the goal to A (or several subgoals).

    -- Basic apply
example (P Q : Prop) (hpq : P → Q) (hp : P) : Q := by
  apply hpq  -- goal becomes P
  exact hp

-- apply with a lemma
example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  apply Nat.le_trans h1  -- transitivity, goal becomes b ≤ c
  exact h2

-- apply producing multiple subgoals
example (n : ℕ) : 0 < n + 1 := by
  apply Nat.succ_pos

    assumption — searches the context for a hypothesis exactly matching the current goal. Lazier than exact and convenient.

    example (P Q R : Prop) (hp : P) (hq : Q) (hr : R) : Q := by
  assumption  -- finds hq : Q

-- Common as the leaf step in branching proofs
example (P Q : Prop) (h : P ∧ Q) : P := by
  obtain ⟨hp, _⟩ := h
  assumption

    constructor — splits the goal into the components of its constructor. For a conjunction P ∧ Q, produces two subgoals P and Q; for an existential ∃ x, P x, you need to provide a witness.

    -- Prove a conjunction
example (n : ℕ) : n ≤ n + 1 ∧ n < n + 2 := by
  constructor
  · linarith  -- first component
  · linarith  -- second component

-- Prove an Iff
example (n : ℕ) : n = 0 ↔ n < 1 := by
  constructor
  · intro h; omega
  · intro h; omega

    left / right — choose the left or right disjunct of P ∨ Q.

    -- Choose the left disjunct
example : 1 = 1 ∨ 1 = 2 := by
  left; rfl

-- Choose by case
example (n : ℕ) (h : n = 0 ∨ n > 0) : n = 0 ∨ n ≥ 0 := by
  cases h with
  | inl h0 => left; exact h0
  | inr hpos => right; linarith

    exfalso — replaces the current goal with False. For "ex falso quodlibet" arguments — usually combined with contradictory hypotheses.

    -- Derive any proposition from a contradiction
example (P : Prop) (h1 : P) (h2 : ¬P) : 0 = 1 := by
  exfalso
  exact h2 h1  -- now the goal is False; h2 h1 : False

-- Combined with linarith
example (n : ℕ) (h1 : n > 5) (h2 : n < 3) : False := by
  linarith  -- linarith closes the goal directly from contradictory hypotheses

    5.3 Negation and Contradiction

    push_neg — pushes negation inward using De Morgan and quantifier-negation rules. Converts ¬∀ x, P x to ∃ x, ¬P x, ¬(P ∧ Q) to P → ¬Q, and so on.

    -- Negate a universal claim
example : ¬ (∀ n : ℕ, n < 10) := by
  push_neg          -- goal becomes ∃ n, 10 ≤ n
  exact ⟨10, le_refl 10⟩

-- Negate an implication
example (P Q : Prop) (h : ¬(P → Q)) : P ∧ ¬Q := by
  push_neg at h  -- h becomes P ∧ ¬Q (push_neg on a hypothesis)
  exact h

-- Nested negation
example : ¬ (∀ x : ℝ, ∃ y : ℝ, y > x) := by
  push_neg   -- goal becomes ∃ x, ∀ y, y ≤ x (an upper bound)
  -- but this proposition is false, so the example can't be completed
  sorry

    contrapose — turns the goal P → Q into its contrapositive ¬Q → ¬P. Sometimes the contrapositive is easier to prove.

    -- If n² is odd, then n is odd (contrapositive: n even → n² even)
theorem odd_sq_imp_odd (n : ℤ) (h : ¬ 2 ∣ n ^ 2) : ¬ 2 ∣ n := by
  contrapose! h   -- goal becomes 2 ∣ n → 2 ∣ n²; contrapose! also pushes negation
  intro ⟨k, hk⟩
  exact ⟨2 * k ^ 2, by rw [hk]; ring⟩

-- Plain contrapose (no push_neg)
example (P Q : Prop) : (P → Q) → (¬Q → ¬P) := by
  intro hpq hnq hp
  exact hnq (hpq hp)

    by_contra h — assumes the negation of the goal as h for proof by contradiction. The new goal becomes False.

    -- Proof-by-contradiction structure
example (P : Prop) : ¬¬P → P := by
  intro hnnp
  by_contra hnp  -- assume ¬P, goal becomes False
  exact hnnp hnp  -- ¬¬P applied to ¬P gives False

-- A more practical example
theorem sqrt2_irrational_sketch : ¬ ∃ (p q : ℕ), q ≠ 0 ∧
    Nat.Coprime p q ∧ (p : ℝ)^2 = 2 * q^2 := by
  intro ⟨p, q, hq, hcop, heq⟩
  -- The detailed argument is involved; sorry to show structure
  sorry

    5.4 Destructuring

    obtain — destructures an existential or conjunction, bringing the components into context. Common alias for rcases.

    -- Destructure ∃ x, P x
example (h : ∃ n : ℕ, n > 5) : ∃ m : ℕ, m > 3 := by
  obtain ⟨n, hn⟩ := h  -- introduce n : ℕ and hn : n > 5
  exact ⟨n, by linarith⟩

-- Destructure P ∧ Q
example (h : (1 : ℕ) < 2 ∧ 2 < 3) : (1 : ℕ) < 3 := by
  obtain ⟨h1, h2⟩ := h  -- h1 : 1 < 2, h2 : 2 < 3
  linarith

-- Nested destructuring
example (h : ∃ n : ℕ, n > 0 ∧ n < 5) : ∃ m : ℕ, m < 10 := by
  obtain ⟨n, hpos, hlt⟩ := h
  exact ⟨n, by linarith⟩

    cases h — case split on the constructors of an inductive type. For h : P ∨ Q, two branches; for h : ℕ, zero and succ branches.

    -- Split on a disjunction
example (h : 2 ∣ n ∨ 2 ∣ (n + 1)) : 2 ∣ n * (n + 1) := by
  cases h with
  | inl h2n => exact Dvd.dvd.mul_right h2n _
  | inr h2n1 => exact Dvd.dvd.mul_left h2n1 _

-- Split on a natural number (zero / successor)
example (n : ℕ) : n = 0 ∨ ∃ m, n = m + 1 := by
  cases n with
  | zero => left; rfl
  | succ m => right; exact ⟨m, rfl⟩

-- Split on Option
example (x : Option ℕ) : x = none ∨ ∃ n, x = some n := by
  cases x with
  | none => left; rfl
  | some n => right; exact ⟨n, rfl⟩

    rcases — recursive case analysis with nested pattern support. More flexible than cases; can destructure several layers at once.

    -- Destructure nested existentials
example (h : ∃ a b : ℕ, a + b = 10) : ∃ n : ℕ, n ≤ 10 := by
  rcases h with ⟨a, b, hab⟩
  exact ⟨a, by omega⟩

-- Destructure each branch of a disjunction
example (h : (n : ℤ) = 2 * k ∨ n = 2 * k + 1) : True := by
  rcases h with heven | hodd <;> trivial

-- Complex nested patterns
example (h : ∃ x : ℕ, x > 0 ∧ (x = 1 ∨ x = 2)) : True := by
  rcases h with ⟨x, hx, h1 | h2⟩ <;> trivial

    use t — supplies a witness t for a goal ∃ x, P x; the goal becomes P t.

    -- Provide a concrete witness
example : ∃ n : ℕ, n * n = 25 := by
  use 5  -- goal becomes 5 * 5 = 25
  norm_num

-- Provide an expression as witness
example (n : ℕ) : ∃ m : ℕ, m = n + 1 := by
  use n + 1  -- goal becomes n + 1 = n + 1
  rfl

-- Multiple use (witnesses and conditions at once)
example : ∃ a b : ℕ, a + b = 7 ∧ a < b := by
  use 3, 4
  norm_num

    5.5 Induction and Recursion

    induction — applies the induction principle of an inductive type. Lean 4's new syntax uses with for branches.

    -- Natural induction: sum of the first n natural numbers = n*(n+1)/2
-- Equivalent form: 2 * ∑ k in Finset.range (n+1), k = n * (n+1)
theorem sum_range_eq (n : ℕ) :
    2 * ∑ k ∈ Finset.range (n + 1), k = n * (n + 1) := by
  induction n with
  | zero =>
    simp  -- base case: n = 0, both sides are 0
  | succ n ih =>
    -- inductive step: assume the case n (ih), prove for n+1
    rw [Finset.sum_range_succ]
    linarith

-- A simpler example: induction on the definition of even
theorem even_add_two (n : ℕ) (h : 2 ∣ n) : 2 ∣ n + 2 := by
  obtain ⟨k, hk⟩ := h
  exact ⟨k + 1, by omega⟩

-- Strong induction
theorem divides_factorial (n k : ℕ) (h : 1 ≤ k) (hk : k ≤ n) : k ∣ n.factorial := by
  exact Nat.factorial_dvd_factorial_of_le hk |>.symm ▸ sorry

    refine — supplies a partial proof term, marking unfilled subgoals with ?_ or named placeholders. Useful for top-down construction.

    -- refine for a conjunction
example (n : ℕ) : n ≤ n + 1 ∧ n < n + 2 := by
  refine ⟨?_, ?_⟩  -- two subgoals
  · omega
  · omega

-- refine combined with a lemma
example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  refine Nat.le_trans ?_ h2  -- first argument unfilled
  exact h1

-- refine with named placeholders
example : ∃ n : ℕ, n > 100 ∧ Nat.Prime n := by
  refine ⟨101, ?gt, ?prime⟩
  case gt => norm_num
  case prime => norm_num

    5.6 Simplification and Search

    simp — rewrites and simplifies using the equational-lemma database. Among the most powerful tactics, and one to use carefully. You can pass extra lemmas, or restrict the lemma set with simp only.

    -- Basic simplification
example (n : ℕ) : n + 0 = n := by simp

-- Simplify with extra lemmas
example (a b : ℝ) (ha : a > 0) : |a| = a := by
  simp [abs_of_pos ha]

-- simp only (just the listed lemmas, avoids surprise rewrites)
example (n m : ℕ) : n + m = m + n := by
  simp only [Nat.add_comm]

-- simp on a hypothesis
example (h : n + 0 = 5) : n = 5 := by
  simp at h  -- h becomes n = 5
  exact h

-- simp [*] uses all available hypotheses as rewrite rules
example (a b : ℕ) (ha : a = 3) (hb : b = 4) : a + b = 7 := by
  simp [ha, hb]

    simp? — runs simp and shows the lemmas it actually used in the Infoview, so you can switch to simp only for speed.

    -- simp? suggests in the Infoview:
-- Try this: simp only [Nat.add_zero, Nat.zero_add, ...]
example (n : ℕ) : n + 0 + 0 = n := by simp?

    exact? — searches Mathlib for a lemma that closes the current goal directly, and shows the suggestion in the Infoview. The fastest way to find a lemma name.

    -- Place the cursor on exact?, the Infoview shows something like:
-- Try this: exact Nat.le_refl n
example (n : ℕ) : n ≤ n := by exact?

-- The lemma exact? finds can replace exact? itself
example (a b : ℤ) (h : a ∣ b) : a ∣ b * 2 := by exact?
-- might suggest: exact h.mul_right 2

    apply? — searches for lemmas that reduce the current goal to a simpler one. Returns a list of candidates; you pick.

    -- apply? suggests applicable lemmas
example (a b c : ℕ) : a + b + c = c + b + a := by
  apply?  -- might suggest a combination of Nat.add_comm and Nat.add_assoc

    norm_cast / push_cast — handle coercions between numeric types, eliminating (↑n : ℝ)-style cast notation so other tactics can handle cross-type equalities and inequalities.

    -- Equality mixing ℕ and ℝ
example (n : ℕ) : (n : ℝ) + 1 = (n + 1 : ℕ) := by norm_cast

-- push_cast pushes casts inward
example (a b : ℕ) : (a + b : ℝ) = (a : ℝ) + (b : ℝ) := by push_cast; ring

-- Common: mixing ℕ and ℤ
example (n : ℕ) (h : (n : ℤ) > 0) : n > 0 := by exact_mod_cast h

-- norm_cast on a cast-laden equality
example (n m : ℕ) (h : (n : ℤ) = (m : ℤ)) : n = m := by exact_mod_cast h

    6. Mathlib Naming Conventions

    Mathlib4 has more than 180,000 lemmas, and knowing the naming patterns is what makes it usable. You don't need to memorize names; you do need to be able to guess names and search effectively.

    6.1 Namespace Structure

    Mathlib organizes namespaces by mathematical structure. Common ones:

    • Nat. — natural numbers (ℕ)
    • Int. — integers (ℤ)
    • Real. — real numbers (ℝ)
    • Rat. — rationals (ℚ)
    • Finset. — finite sets
    • List. — lists
    • Polynomial. — polynomials
    • Matrix. — matrices
    • Complex. — complex numbers

    6.2 Naming Patterns

    Mathlib lemma names follow a few core patterns:

    -- Pattern 1: property_of_condition
-- "property given condition"
#check Nat.lt_of_add_lt_add_left  -- a + b < a + c → b < c
#check Int.pos_of_ne_zero_of_nonneg  -- n ≠ 0 → 0 ≤ n → 0 < n

-- Pattern 2: object.operation_target
-- "operation on object related to target"
#check Nat.add_comm    -- n + m = m + n
#check Nat.mul_comm    -- n * m = m * n
#check Int.add_comm    -- n + m = m + n on ℤ

-- Pattern 3: property_property (relation between two properties)
#check Nat.even_add_odd   -- even n → odd m → odd (n + m)
#check Int.even_mul_succ_self  -- 2 ∣ n * (n + 1)

-- Pattern 4: Finset operations
#check Finset.sum_add_distrib  -- ∑ i, (f i + g i) = ∑ i, f i + ∑ i, g i
#check Finset.prod_congr       -- equal sets give equal products

-- Pattern 5: real analysis
#check Real.sqrt_sq    -- 0 ≤ x → √(x²) = x
#check Real.sq_sqrt    -- 0 ≤ x → (√x)² = x
#check Real.log_mul    -- x > 0 → y > 0 → log(xy) = log x + log y

    6.3 Suffix Conventions

    -- _iff: if-and-only-if (most general)
#check Nat.lt_iff_add_one_le  -- n < m ↔ n + 1 ≤ m

-- _eq: equational form
#check Nat.succ_eq_add_one    -- n.succ = n + 1

-- _le: less-than-or-equal
#check Nat.le_add_left        -- n ≤ m + n

-- _lt: strict less-than
#check Nat.lt_add_one         -- n < n + 1

-- _pos: positivity
#check Nat.pos_of_ne_zero     -- n ≠ 0 → 0 < n

-- _nonneg: non-negativity
#check Int.natAbs_nonneg      -- 0 ≤ n.natAbs (always true since natAbs : ℕ)
#check sq_nonneg              -- 0 ≤ x ^ 2

-- _comm: commutativity
-- _assoc: associativity
-- _distrib: distributivity
#check mul_add   -- a * (b + c) = a * b + a * c (left distributivity)
#check add_mul   -- (a + b) * c = a * c + b * c (right distributivity)

    7. Patterns for Formalizing Competition Math

    Based on formalizing 18 ICCM problems, here are typical patterns and tactic combinations by problem type.

    7.1 Algebraic Identities

    Algebraic identities are the easiest to formalize. ring handles almost any polynomial identity; for fractions, clear denominators with field_simp first, then ring.

    -- Square expansion: (a + b)² = a² + 2ab + b²
theorem sq_expand (a b : ℝ) : (a + b)^2 = a^2 + 2*a*b + b^2 := by ring

-- Difference of cubes: a³ - b³ = (a-b)(a² + ab + b²)
theorem cube_diff (a b : ℝ) : a^3 - b^3 = (a - b) * (a^2 + a*b + b^2) := by ring

-- Multivariate identity
theorem three_var_identity (a b c : ℝ) :
    (a + b + c)^2 = a^2 + b^2 + c^2 + 2*(a*b + b*c + a*c) := by ring

-- Vieta-style relations (for polynomial roots)
theorem vieta_check (p q r : ℝ) :
    (p + q + r) * (p*q + q*r + p*r) - p*q*r =
    p^2*q + p^2*r + q^2*p + q^2*r + r^2*p + r^2*q := by ring

-- Identity with fractions (field_simp first, then ring)
theorem frac_identity (a b : ℝ) (ha : a ≠ 0) (hb : b ≠ 0) :
    1/a + 1/b = (a + b) / (a * b) := by
  field_simp
  ring

    7.2 Integers and Divisibility

    Useful tools for divisibility proofs: dvd_intro (provide a witness), Nat.dvd_add (additivity of divisibility), omega (modular arithmetic). For mod, Int.emod_emod_of_dvd is handy.

    -- 6 divides n(n+1)(n+2)
-- Strategy: among n, n+1, n+2 there's one even and one multiple of 3
theorem six_dvd_consec_prod (n : ℤ) : 6 ∣ n * (n + 1) * (n + 2) := by
  have h2 : 2 ∣ n * (n + 1) * (n + 2) := by
    have := Int.even_mul_succ_self n  -- 2 ∣ n*(n+1)
    exact this.mul_right (n + 2)
  have h3 : 3 ∣ n * (n + 1) * (n + 2) := by
    have := Int.three_dvd_iff_sum_digits -- this lemma may not exist; use omega/rcases instead
    omega
  sorry -- full proof needs Int.Coprime → divides product

-- Simpler divisibility: 2 ∣ n(n+1)
theorem two_dvd_n_mul_succ (n : ℤ) : 2 ∣ n * (n + 1) := by
  rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
  · -- n is even
    exact ⟨k * (n + 1), by rw [hk]; ring⟩
  · -- n is odd (so n+1 is even)
    exact ⟨n * (k + 1), by rw [hk]; ring⟩

-- Divisibility example with omega
theorem dvd_by_omega_example (n : ℤ) : 2 ∣ n^2 + n := by
  have factored : n^2 + n = n * (n + 1) := by ring
  rw [factored]
  exact two_dvd_n_mul_succ n

-- Divisibility on ℕ
theorem nat_dvd_example : 12 ∣ 3 * 4 * 5 - 3 * 4 := by norm_num

-- dvd_trans
theorem dvd_trans_example (a b c : ℤ) (h1 : a ∣ b) (h2 : b ∣ c) : a ∣ c :=
  dvd_trans h1 h2

    7.3 Inequalities

    Competition inequalities usually need classical inequalities (AM-GM, Cauchy-Schwarz) as lemmas, or a sum-of-squares decomposition closed by nlinarith.

    -- AM-GM: a² + b² ≥ 2ab
theorem am_gm_sq (a b : ℝ) : a^2 + b^2 ≥ 2 * a * b := by
  nlinarith [sq_nonneg (a - b)]

-- More general AM-GM (two positive numbers)
theorem am_gm_pos (a b : ℝ) (ha : a > 0) (hb : b > 0) : a + b ≥ 2 * Real.sqrt (a * b) := by
  sorry -- needs Real.sqrt lemmas; structure shown

-- Cauchy-Schwarz (finite-sum version)
-- (∑ a_i b_i)² ≤ (∑ a_i²) * (∑ b_i²)
-- Available in Mathlib as inner_mul_le_norm_mul_norm

-- Triangle inequality
theorem triangle_ineq_sq (a b c : ℝ) (ha : 0 < a) (hb : 0 < b) (hc : 0 < c)
    (h : a + b > c) (h2 : b + c > a) (h3 : a + c > b) :
    a^2 + b^2 + c^2 < (a + b + c)^2 / 2 + (a*b + b*c + a*c) := by
  nlinarith [sq_nonneg (a - b), sq_nonneg (b - c), sq_nonneg (a - c)]

-- Combining basic inequalities
theorem ineq_combination (x y z : ℝ) (hx : x ≥ 0) (hy : y ≥ 0) (hz : z ≥ 0)
    (hxyz : x + y + z = 1) : x*y + y*z + x*z ≤ 1/3 := by
  nlinarith [sq_nonneg (x - y), sq_nonneg (y - z), sq_nonneg (x - z)]

    7.4 Existence and Constructive Proofs

    An existence proof usually means producing an explicit witness and verifying the conditions. Sometimes you have to split into cases to determine the witness.

    -- Simple existence: there is an even number greater than 100
theorem exists_even_gt_100 : ∃ n : ℕ, n > 100 ∧ 2 ∣ n := by
  use 102
  norm_num

-- Parametric existence: for any n, there's a prime > n
-- (Mathlib already has Nat.exists_infinite_primes)
theorem exists_prime_gt (n : ℕ) : ∃ p : ℕ, p > n ∧ Nat.Prime p :=
  Nat.exists_infinite_primes (n + 1) |>.imp fun p ⟨hp_ge, hp_prime⟩ =>
    ⟨Nat.lt_of_succ_le hp_ge, hp_prime⟩

-- Use divisibility to construct a witness
theorem exists_multiple (n k : ℤ) (hk : k ≠ 0) (h : k ∣ n) :
    ∃ m : ℤ, n = k * m := by
  exact h  -- the definition of ∣ is precisely such an m

-- Constructive proof: rational-root condition for a quadratic
-- if a, b, c ∈ ℤ and b² - 4ac = d² for some integer d, the equation has a rational root
theorem rational_root_exists (a b c d : ℤ) (ha : a ≠ 0)
    (h : b^2 - 4*a*c = d^2) :
    ∃ p q : ℤ, q ≠ 0 ∧ a * p^2 + b * p * q + c * q^2 = 0 := by
  use -b + d, 2 * a
  constructor
  · intro h2a; exact ha (by linarith [h2a])
  · nlinarith [sq_nonneg d]

    7.5 Inductive Proofs

    Mathematical induction in Lean 4 uses the induction tactic. The key is identifying the inductive hypothesis (ih) and using it in the inductive step.

    -- Classic induction: ∑_{k=0}^{n} k = n(n+1)/2
-- In Lean 4, prove 2 * sum = n*(n+1) to avoid fractions
theorem gauss_sum (n : ℕ) :
    2 * ∑ k ∈ Finset.range (n + 1), k = n * (n + 1) := by
  induction n with
  | zero => simp
  | succ n ih =>
    rw [Finset.sum_range_succ]
    push_cast
    linarith

-- Induction on a divisibility property
-- 3 | 4^n - 1 for all n : ℕ
theorem three_dvd_pow4_sub1 (n : ℕ) : 3 ∣ 4^n - 1 := by
  induction n with
  | zero => simp
  | succ n ih =>
    have : (4 : ℤ)^(n + 1) - 1 = 4 * (4^n - 1) + 3 := by ring
    -- need to switch to ℤ to avoid ℕ subtraction truncation
    sorry

-- Inductive version on ℤ
theorem three_dvd_pow4_sub1' (n : ℕ) : (3 : ℤ) ∣ 4^n - 1 := by
  induction n with
  | zero => norm_num
  | succ n ih =>
    have key : (4 : ℤ)^(n + 1) - 1 = 4 * (4^n - 1) + 3 := by ring
    rw [key]
    exact dvd_add (dvd_mul_of_dvd_right ih 4) (dvd_refl 3)

-- Strong induction: Fibonacci property
-- structure only
theorem fib_property (n : ℕ) : True := by
  induction n using Nat.strong_induction_on with
  | _ n ih => trivial

    8. Worked Examples — From Paper to Lean

    This section walks through translating concrete problems from intuitive proof to complete Lean 4 code, including mistakes and fixes along the way.

    8.1 Example One: (a+b)² ≡ a² + b² (mod 2)

    Problem: for any integers a, b, prove (a+b)² ≡ a² + b² (mod 2).

    Paper analysis: (a+b)² = a² + 2ab + b², so (a+b)² − (a² + b²) = 2ab, a multiple of 2, so (a+b)² and a² + b² are congruent mod 2.

    Step 1: sketch with sorry.

    -- State the proposition first, prove later
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  sorry  -- placeholder, check the statement is right

    Step 2: choose a strategy. The key identity is (a+b)² − (a² + b²) = 2ab. On ℤ, omega handles linear integer arithmetic, but expanding (a+b)² involves multiplication, so simplify with ring or a have first.

    -- Step 2: add the key have
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  have h : (a + b)^2 - (a^2 + b^2) = 2 * (a * b) := by ring
  -- h says the difference is a multiple of 2
  -- omega knows: if x - y = 2 * k, then x % 2 = y % 2
  omega

    This proof is correct. ring establishes the algebraic identity and omega handles the modular linear part. omega picks up all integer equalities/inequalities in context, including h, so it can derive the goal.

    Clean version:

    import Mathlib

-- Final version
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  have h : (a + b)^2 - (a^2 + b^2) = 2 * (a * b) := by ring
  omega

    8.2 Example Two: n² + n is always even

    Problem: for any integer n, prove 2 ∣ n² + n.

    Paper analysis: n² + n = n(n+1); n and n+1 are consecutive integers, one of them is even, so the product is even.

    Wrong first attempt:

    -- Wrong: directly provide a witness (the witness isn't an integer!)
theorem n_sq_plus_n_even_wrong (n : ℤ) : 2 ∣ n^2 + n := by
  use n * (n + 1) / 2  -- wrong: ℤ division isn't exact and truncates
  ring  -- fails because ring can't handle integer division

    Correct method one: case split (n even or odd)

    theorem n_sq_plus_n_even (n : ℤ) : 2 ∣ n^2 + n := by
  have factored : n^2 + n = n * (n + 1) := by ring
  rw [factored]
  -- need to show 2 ∣ n * (n + 1)
  rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
  · -- n is even: n = 2k
    exact ⟨k * (n + 1), by rw [hk]; ring⟩
  · -- n is odd: n = 2k + 1, so n + 1 = 2k + 2 = 2(k+1)
    exact ⟨n * (k + 1), by rw [hk]; ring⟩

    Correct method two: omega (more concise)

    -- omega handles it directly: n^2 + n = n*(n+1), and 2 ∣ n*(n+1)
-- omega is for linear integers, but 2 ∣ n^2 + n simplifies to a form omega can handle
theorem n_sq_plus_n_even' (n : ℤ) : 2 ∣ n^2 + n := by
  have : n^2 + n = n * (n + 1) := by ring
  rw [this]
  have : 2 ∣ n * (n + 1) := by
    rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
    · exact ⟨k * (n + 1), by linarith [hk]⟩
    · exact ⟨n * (k + 1), by linarith [hk]⟩
  exact this

    8.3 Example Three: Full Inductive Proof

    Problem: for all natural numbers n, prove 3 ∣ n³ − n (i.e., n³ ≡ n (mod 3)).

    -- Method 1: algebraic factoring
-- n³ - n = n(n-1)(n+1) = (n-1)n(n+1), product of three consecutive integers
theorem three_dvd_cube_minus (n : ℤ) : 3 ∣ n^3 - n := by
  have factored : n^3 - n = (n - 1) * n * (n + 1) := by ring
  rw [factored]
  -- Among three consecutive integers, one is a multiple of 3
  -- Split on n mod 3
  have hmod : n % 3 = 0 ∨ n % 3 = 1 ∨ n % 3 = 2 := by omega
  rcases hmod with h0 | h1 | h2
  · -- 3 ∣ n
    have hn : 3 ∣ n := ⟨n / 3, by omega⟩
    exact dvd_mul_of_dvd_right (dvd_mul_of_dvd_right hn _) _
  · -- 3 ∣ n - 1 (n ≡ 1 mod 3, so n - 1 ≡ 0 mod 3)
    have hn1 : 3 ∣ n - 1 := ⟨(n - 1) / 3, by omega⟩
    exact dvd_mul_of_dvd_left (dvd_mul_of_dvd_left hn1 _) _
  · -- 3 ∣ n + 1 (n ≡ 2 ≡ -1 mod 3)
    have hn1 : 3 ∣ n + 1 := ⟨(n + 1) / 3, by omega⟩
    exact dvd_mul_of_dvd_right (dvd_mul_of_dvd_left hn1 _) _

-- Method 2: induction
theorem three_dvd_cube_minus_induction (n : ℤ) : 3 ∣ n^3 - n := by
  have : n^3 - n = n * (n - 1) * (n + 1) := by ring
  rw [this]
  omega  -- omega closes the goal directly! it handles divisibility by 3 of three consecutive integers

    Method 2 closes the divisibility-by-3 reasoning directly with omega, which is one of the more useful capabilities of omega in Lean 4.

    9. Common Errors and How to Fix Them

    9.1 ℕ Truncating Subtraction

    This is the trap beginners hit most often. In Lean 4, subtraction on ℕ truncates: 3 - 5 = 0, not -2. That's at odds with mathematical intuition and leads to mysterious proof failures.

    -- Example
#eval (3 : ℕ) - 5    -- outputs 0, not -2

-- The following fails because a - b on ℕ doesn't mean what we think
-- example (a b : ℕ) (h : a ≥ b) : (a - b) + b = a := by ring  -- ring fails

-- Fix: work over ℤ, or use Nat.sub_add_cancel
example (a b : ℕ) (h : b ≤ a) : a - b + b = a := Nat.sub_add_cancel h

-- For negatives, switch to ℤ
example (a b : ℤ) : (a - b) + b = a := by ring  -- ring works on ℤ

-- Cast ℕ to ℤ
example (n m : ℕ) (h : n ≤ m) : (n : ℤ) - m ≤ 0 := by
  have : (n : ℤ) ≤ (m : ℤ) := Int.ofNat_le.mpr h
  linarith

    9.2 Type Mismatches

    Lean 4 has a strong type system. ℕ, ℤ, ℚ, ℝ are different types and mixing them produces errors. The error message usually says type mismatch: expected ℝ, got ℕ.

    -- Type mismatch
-- example (n : ℕ) (x : ℝ) : n + x = x + n := by ring  -- fails

-- Fix: explicit cast
example (n : ℕ) (x : ℝ) : (n : ℝ) + x = x + (n : ℝ) := by ring

-- norm_cast handles casts
example (n m : ℕ) (h : n < m) : (n : ℝ) < (m : ℝ) := by exact_mod_cast h

-- push_cast pushes casts into the expression
example (n m : ℕ) : ((n + m : ℕ) : ℝ) = (n : ℝ) + (m : ℝ) := by push_cast; ring

-- Common pattern: derive on ℕ, need an inequality on ℝ
example (n : ℕ) (h : n > 0) : (n : ℝ) > 0 := by exact Nat.cast_pos.mpr h

    9.3 omega Doesn't Handle Multiplication

    omega handles only linear integer arithmetic; variable products produce errors or no progress.

    -- omega fails
-- example (n : ℤ) : n^2 ≥ 0 := by omega  -- fails: n^2 is nonlinear

-- Use sq_nonneg instead
example (n : ℤ) : n^2 ≥ 0 := sq_nonneg n

-- Another failure:
-- example (a b : ℤ) : a * b = b * a := by omega  -- fails

-- Use ring (commutativity of multiplication)
example (a b : ℤ) : a * b = b * a := by ring

-- Combine omega with nlinarith
-- Use ring to reduce to linear form, then omega
example (n : ℤ) : n^2 + 2*n + 1 = (n + 1)^2 := by ring  -- ring closes it directly

    9.4 ring Fails on ℕ

    ring works in a ring, and ℕ isn't a ring (no additive inverses, i.e., no real subtraction). Equalities involving subtraction on ℕ make ring fail.

    -- ring fails on ℕ
-- example (a b : ℕ) : (a + b) - b = a := by ring  -- fails

-- Fix 1: work on ℤ
example (a b : ℕ) : (a : ℤ) + b - b = a := by ring

-- Fix 2: dedicated lemma
example (a b : ℕ) (h : b ≤ a + b) : (a + b) - b = a := Nat.add_sub_cancel

-- Fix 3: omega (handles some ℕ subtraction cases)
example (a b : ℕ) (h : b ≤ a) : a - b + b = a := by omega

    9.5 Lemma Renames

    Mathlib4 is under active development and lemma names occasionally change. Don't memorize names — use exact? or apply? to confirm each time.

    -- Bad: hard-coding a possibly-stale name
-- exact Nat.lt_of_sub_eq_succ h  -- this name may have changed

-- Good: search with exact?
example (n m : ℕ) (h : n ≤ m) : n < m + 1 := by exact?
-- exact? returns the current correct lemma name

-- Better habit: for simple relations, use a tactic instead of a named lemma
example (n : ℕ) : n < n + 1 := by omega  -- doesn't depend on a specific name

    10. Advanced — Automation Tactics

    More advanced automation tactics in Mathlib4 that handle a lot of tedious but regular proofs.

    10.1 aesop

    aesop (Automated Extensional Situation/Object Prover) is Lean 4's general-purpose automation, doing forward/backward search through a rules database. Suitable for structural proofs — set operations, logical deductions, and so on.

    -- aesop on set operations
example (s t : Finset ℕ) (h : s ⊆ t) (x : ℕ) (hx : x ∈ s) : x ∈ t := by
  aesop  -- or: exact h hx

-- aesop on type-class proofs
example (α : Type*) (s : Finset α) : s.card ≥ 0 := by aesop

    10.2 positivity

    positivity is dedicated to proving that an expression is positive or non-negative. It handles products, powers, absolute values, square roots, and so on.

    -- Positivity
example (a b : ℝ) (ha : 0 < a) (hb : 0 < b) : 0 < a * b := by positivity

-- Non-negativity
example (a : ℝ) : 0 ≤ a ^ 2 := by positivity

-- Compound expressions
example (n : ℕ) (a : ℝ) (ha : 0 < a) : 0 < a ^ n + 1 := by positivity

-- More goal-directed than nlinarith
example (x y : ℝ) (hx : 0 < x) (hy : 0 ≤ y) : 0 ≤ x^2 * y + x := by positivity

    10.3 field_simp

    field_simp clears denominators in a field, turning a goal with division into one without, after which ring can close it. You need to prove the denominators are non-zero first.

    -- Clear denominators, then ring
example (a b : ℝ) (ha : a ≠ 0) (hb : b ≠ 0) :
    (a + b) / (a * b) = 1/b + 1/a := by
  field_simp
  ring

-- Multiple denominators
example (x y z : ℝ) (hx : x ≠ 0) (hy : y ≠ 0) (hz : z ≠ 0) :
    1/x + 1/y + 1/z = (y*z + x*z + x*y) / (x*y*z) := by
  field_simp
  ring

    10.4 norm_cast and exact_mod_cast

    This family of tactics handles coercions between numeric types. norm_cast normalizes casts in the goal; exact_mod_cast and apply_mod_cast ignore cast differences when supplying or applying a proof.

    -- norm_cast as a closing tactic
example (n m : ℕ) (h : n ≤ m) : (n : ℤ) ≤ (m : ℤ) := by exact_mod_cast h

-- norm_cast normalizes casts
example (n : ℕ) : (n : ℝ) + 0 = n := by norm_cast

-- push_cast pushes casts inward
example (n m : ℕ) : ((n * m : ℕ) : ℝ) = (n : ℝ) * (m : ℝ) := by push_cast; ring

-- Combined
theorem cast_ineq_example (n : ℕ) (h : n > 0) : (n : ℝ) > 0 := by
  exact_mod_cast h

    10.5 decide and native_decide

    decide verifies decidable propositions through kernel evaluation; native_decide JIT-compiles the check, faster on big computations.

    -- decide: small-scale
example : Nat.Prime 31 := by decide
example : ¬ (4 : ℕ) ∣ 10 := by decide

-- native_decide: large numbers
example : Nat.Prime 65537 := by native_decide  -- a Fermat number; decide is slow here
example : (Finset.range 100).card = 100 := by native_decide

-- decide on universally quantified finite types
example : ∀ b : Bool, b || true = true := by decide

-- Sometimes norm_num is faster than decide
example : Nat.Prime 1000003 := by norm_num  -- norm_num is optimized for primality

    10.6 simp_arith

    simp_arith combines simp with arithmetic rules. Useful when simp alone isn't enough but omega is too weak.

    -- simp_arith handles simplification with arithmetic
example (n : ℕ) (h : n ≥ 1) : n + n ≥ 2 := by simp_arith
example (n : ℕ) : 0 + n = n := by simp_arith

    10.7 Picking a Tactic

    When facing a goal, this decision flow helps pick a tactic quickly:

    • Polynomial equality? Try ring; clear denominators with field_simp first if needed
    • Specific numerical claim? norm_num
    • Linear ℤ/ℕ? omega
    • Linear ℝ inequality? linarith; if non-linear, nlinarith [sq_nonneg ...]
    • Positivity / non-negativity? positivity
    • Goal involves a lemma you don't know the name of? exact? or apply?
    • Cast in the goal? norm_cast or exact_mod_cast
    • Decidable, finite proposition? decide or native_decide
    • Want simp's effect with precise control? simp only [...]
    -- Combined example: for any integer n, (2n+1)² ≡ 1 (mod 8)
theorem odd_sq_mod8 (n : ℤ) : (2*n + 1)^2 % 8 = 1 := by
  have expand : (2*n + 1)^2 = 4*n^2 + 4*n + 1 := by ring  -- ring expands
  rw [expand]
  have factored : 4*n^2 + 4*n = 4 * (n^2 + n) := by ring  -- ring factors
  rw [factored]
  have two_dvd : 2 ∣ n^2 + n := by
    have : n^2 + n = n * (n + 1) := by ring
    rw [this]
    rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
    · exact ⟨k * (n + 1), by rw [hk]; ring⟩
    · exact ⟨n * (k + 1), by rw [hk]; ring⟩
  obtain ⟨m, hm⟩ := two_dvd
  rw [hm]
  ring_nf
  omega  -- final linear arithmetic
