    Lean 4 入门路径

    ← Learning

    本指南面向有数学背景但无类型论经验的读者，基于形式化 18 道 ICCM 竞赛题的实践总结。

    1. 为什么选 Lean 4

    常用的定理证明器有四个：Coq（法国 INRIA，OCaml 实现）、Isabelle/HOL（剑桥/慕尼黑，ML 系）、Agda（瑞典 Chalmers，依赖类型）和 Lean 4（微软研究院/Leanprover 社区，C++/Lean 自举）。本文基于形式化 ICCM 竞赛题的实际需要，以下比较各系统的差异，说明选用 Lean 4 的理由。

    与 Coq 的比较。Coq 拥有数十年积累，但语法相对繁琐，策略（tactic）语言 Ltac 与主语言割裂，学习曲线陡峭。数学库 MathComp 虽然成熟，但命名风格晦涩，对竞赛题涉及的实数分析、组合数学覆盖并不全面。Lean 4 的 Mathlib4 在覆盖广度上已经超越 MathComp，且策略语法与主语言统一，更接近数学家的习惯。

    与 Isabelle 的比较。Isabelle/HOL 的自动化能力（sledgehammer）极强，能调用外部 SMT/ATP 求解器，对于需要大量繁琐代数推导的题目非常有效。但 Isabelle 的类型系统相对弱，表达能力不如依赖类型系统，且社区主要集中在欧洲学术圈，中文资源极少。Lean 4 的 decide、norm_num、omega 等策略在竞赛场景下已足够强大。

    与 Agda 的比较。Agda 是依赖类型研究的前沿工具，表达能力最强，但几乎没有面向数学竞赛的库。形式化一道初等数论题在 Agda 中需要从头搭建大量基础设施，不适合以"完成形式化"为目标的工作。

    Mathlib4 的覆盖范围。截至 2025 年，Mathlib4 已包含超过 18 万条引理，覆盖初等数论、线性代数、多项式理论、实分析、复分析、组合数学、代数拓扑、范畴论等领域。对于 ICCM 竞赛题这一层次的数学，所需的绝大多数工具都已有现成引理可用，不需要从头证明。

    活跃社区与持续开发。Lean 4 由 Leonardo de Moura 主导开发，Mathlib4 贡献者超过 500 人，每周持续有新引理合并。社区讨论在 Zulip（leanprover.zulipchat.com）上进行。

    为何适合形式化 ICCM 题目。ICCM 竞赛题以代数、数论、组合为主，Mathlib4 在这些领域的覆盖较为充分。Lean 4 的策略语言结构接近手写证明：用 have 引入中间步骤，用 ring 处理代数恒等式，用 linarith 处理不等式，整体结构与纸面证明对应关系清晰。

    2. 环境配置

    以下步骤适用于 Windows 10/11、macOS 和主流 Linux 发行版。建议优先在 Linux/macOS 下工作，因为 Lean 4 的工具链在这些平台上更成熟，构建速度更快。

    2.1 安装 elan（Lean 版本管理器）

    elan 是 Lean 4 的版本管理工具，类似于 Rust 的 rustup。在终端中运行：

    # Linux / macOS
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh

# Windows（PowerShell，需要先安装 curl 或使用 winget）
winget install leanprover.elan
# 或直接下载 elan-init.exe 并运行

    安装完成后重启终端，运行 elan --version 验证安装成功。elan 会自动管理不同项目所需的 Lean 工具链版本，无需手动切换。

    2.2 创建新项目

    使用 Lake（Lean 的构建系统）创建一个使用 Mathlib4 的新项目：

    lake new myproject math
cd myproject

    math 参数告诉 Lake 使用数学模板，会自动生成依赖 Mathlib4 的 lakefile.toml。你也可以手动配置该文件：

    import Lake
open Lake DSL

package «myproject» where
  name := "myproject"

require mathlib from git
  "https://github.com/leanprover-community/mathlib4" @ "v4.27.0"

lean_lib «Myproject» where

    版本号 v4.27.0 指定了 Mathlib4 的具体版本。建议锁定版本以保证可重现性；当需要升级时，修改此处版本号并重新运行 lake update。

    2.3 下载 Mathlib 缓存

    Mathlib4 的源代码本身需要数小时才能从零编译，但社区提供了预编译的二进制缓存（约 1–2 GB）。在项目根目录运行：

    lake exe cache get

    这会从 Mathlib 服务器下载与当前工具链版本匹配的编译缓存。下载完成后，lake build 只需几分钟而非数小时。如果网络速度较慢，可以考虑使用镜像或在有良好网络的机器上提前下载。

    2.4 VS Code 配置

    在 VS Code 扩展市场搜索并安装 lean4（扩展 ID：leanprover.lean4）。该扩展会：

    • 自动检测项目中的 lakefile.toml 并配置语言服务器
    • 在右侧显示 Lean Infoview 面板（快捷键 Ctrl+Shift+Enter 切换）
    • 光标移动时实时更新当前证明状态
    • 提供代码补全、引理搜索、语法高亮

    打开项目后，VS Code 底部状态栏会显示 Lean 服务器的加载状态。首次打开需要等待语言服务器启动（通常 30 秒到 2 分钟）。当你在 by 关键字后的策略块中移动光标时，Infoview 会显示如下格式的证明状态：

    ⊢ n * (n + 1) % 2 = 0
-- 上方是目标 (goal)
-- 假设列表：
a b : ℤ
h : a + b = 0

    2.5 验证安装

    在 Myproject.lean 中写入以下代码，如果 Infoview 不报错且能自动完成，则安装成功：

    import Mathlib

-- 验证 Mathlib 可用
#check Nat.add_comm
#eval 2 + 3  -- 应输出 5

theorem hello_lean : 1 + 1 = 2 := by norm_num

    3. 核心概念：命题即类型

    理解 Lean 4 最重要的一步是接受 Curry-Howard 同构（命题即类型，证明即程序）这一核心思想。这不只是哲学比喻，而是 Lean 4 的实现基础。

    3.1 命题即类型

    在 Lean 4 中，每一个命题（proposition）都是一个类型（type），而该命题的一个证明就是该类型的一个项（term）。具体地说：

    • 1 + 1 = 2 是一个类型（命题类型）
    • 提供该命题的证明，等同于构造一个属于该类型的项
    • theorem foo : P := proof_term 宣告 foo 是类型 P 的一个项

    这意味着"证明一个命题"和"写一个函数"在本质上是同一件事。蕴含 P → Q 就是从 P 类型的项到 Q 类型的项的函数类型；全称量化 ∀ x, P x 就是依赖函数类型（dependent function type）；存在量化 ∃ x, P x 就是依赖对类型（dependent pair type）。

    -- 命题 P → Q 的证明就是一个函数
-- 给定 h : P（类型 P 的项），返回 Q 的项
theorem modus_ponens (P Q : Prop) (hpq : P → Q) (hp : P) : Q :=
  hpq hp  -- 直接用函数应用

-- 全称量化：∀ n : ℕ, 0 ≤ n
-- 等同于：依赖函数，对每个 n 返回 0 ≤ n 的证明
theorem zero_le_all : ∀ n : ℕ, 0 ≤ n := Nat.zero_le

    3.2 策略模式（Tactic Mode）

    直接书写证明项（term-mode proof）对于复杂命题往往非常困难，因为需要在脑中同时管理整个类型结构。Lean 4 提供了 策略模式（tactic mode），通过 by 关键字进入。策略模式允许你逐步分解目标，每一步只需要关注当前的证明状态。

    -- 项模式（Term Mode）：直接给出证明项
theorem add_comm_example (a b : ℕ) : a + b = b + a :=
  Nat.add_comm a b

-- 策略模式（Tactic Mode）：用 by 关键字进入
theorem add_comm_example' (a b : ℕ) : a + b = b + a := by
  exact Nat.add_comm a b  -- exact 提供精确的证明项

-- 更复杂的例子，展示逐步分解
theorem example_tactic (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  exact Nat.le_trans h1 h2

    3.3 Infoview 读法

    在策略模式中，Infoview 是你的主要导航工具。理解 Infoview 的格式对高效证明至关重要：

    -- 将光标放在某行策略之后，Infoview 显示该行执行后的状态
-- 格式如下：
--
-- case left
-- a b : ℤ
-- h : a > 0
-- ⊢ a + b > b
--
-- 解读：
-- "case left"  — 当前处于 constructor/cases 的哪个分支
-- "a b : ℤ"   — 上下文中已有的变量及其类型
-- "h : a > 0"  — 上下文中的假设，h 是它的名字
-- "⊢ a + b > b" — 需要证明的目标（⊢ 读作"turnstile"）

-- 目标为 No goals 时，证明完成
theorem simple_example (a b : ℤ) (h : a > 0) : a + b > b := by
  linarith  -- 执行后 Infoview 显示 "No goals"

    当你不确定下一步该怎么做时，最有效的方法是：看清当前目标的形式，然后选择匹配该形式的策略。本指南第 5 节详细介绍了各类策略的适用场景。

    3.4 sorry 占位符

    sorry 是 Lean 4 的"万能证明项"——它可以填入任何目标，但会产生警告。在证明复杂定理时，先用 sorry 占位勾勒出整体结构，然后逐步填充，是常用的工作流程。注意：含有 sorry 的文件虽然通过类型检查，但 lake build 会报警告，不能算作完成形式化。

    -- 使用 sorry 搭建证明框架
theorem complex_theorem (n : ℕ) : n * (n + 1) % 2 = 0 := by
  sorry  -- 待填充

-- 分步填充
theorem complex_theorem' (n : ℕ) : n * (n + 1) % 2 = 0 := by
  have h : n * (n + 1) = 2 * (n * (n + 1) / 2) := by sorry
  sorry

    4. 基础语法

    4.1 定义与检查

    -- def 定义常量或函数
def myNat : ℕ := 42
def double (n : ℕ) : ℕ := 2 * n
def add3 (a b c : ℕ) : ℕ := a + b + c

-- #check 查询类型（不求值）
#check myNat         -- myNat : ℕ
#check double        -- double : ℕ → ℕ
#check Nat.add_comm  -- Nat.add_comm : ∀ (n m : ℕ), n + m = m + n

-- #eval 求值（运行时计算）
#eval double 21      -- 42
#eval 2 ^ 10         -- 1024
#eval Nat.gcd 12 8   -- 4

    4.2 函数类型

    -- 简单函数类型：A → B
def f : ℕ → ℕ := fun n => n + 1

-- 多参数函数（柯里化）：A → B → C
def g : ℕ → ℕ → ℕ := fun a b => a * b

-- 依赖类型：∀ (n : ℕ), P n
-- 在数学中表示"对所有 n，命题 P n 成立"
def h : ∀ (n : ℕ), n + 0 = n := fun n => Nat.add_zero n

-- 匿名函数（lambda）
#check fun (x : ℝ) => x ^ 2   -- ℝ → ℝ
#eval (fun x => x + 1) 5       -- 6

-- 模式匹配
def factorial : ℕ → ℕ
  | 0     => 1
  | n + 1 => (n + 1) * factorial n

#eval factorial 5  -- 120

    4.3 theorem 与 have / show / exact

    -- theorem 声明一个定理
theorem nat_add_zero (n : ℕ) : n + 0 = n := by
  exact Nat.add_zero n

-- have 引入中间步骤（局部命名）
theorem transitivity_example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  have step : a ≤ c := Nat.le_trans h1 h2  -- 命名为 step
  exact step

-- have 的另一种写法（内联证明）
theorem example_with_have (n : ℕ) : n + n = 2 * n := by
  have : n + n = 2 * n := by ring  -- 匿名 have，名为 this
  exact this

-- show 改写当前目标的显示形式（定义等价时有用）
theorem show_example (n : ℕ) : n * 2 = n + n := by
  show n * 2 = n + n  -- 明确当前要证什么
  ring

-- exact 提供完全匹配目标的证明项
theorem exact_example : 1 + 1 = 2 := by
  exact rfl  -- rfl 是自反性，对可计算的等式直接成立

-- from 是 exact 的别名（更像英语语序）
theorem from_example (h : 1 = 1) : 1 = 1 := by
  exact h

    4.4 变量与命名空间

    -- variable 声明全局变量（在文件内所有定理共享）
variable (n m k : ℕ)
variable (a b c : ℝ)

-- namespace 组织代码
namespace MyLemmas

theorem double_add (x : ℤ) : x + x = 2 * x := by ring

end MyLemmas

-- 使用时需加命名空间前缀
#check MyLemmas.double_add

-- open 打开命名空间（避免重复写前缀）
open Nat in
#check succ_pos  -- 等价于 Nat.succ_pos

    5. Tactic 详解

    策略（tactic）是 Lean 4 证明的核心工具。以下按功能分类，每个策略给出定义、适用场景和完整代码示例。

    5.1 自动化求解类

    ring — 证明交换环（commutative ring）中的多项式等式。它通过规范化两侧表达式来判断是否相等，可处理加、减、乘、幂。无法处理除法（除非在域上用 field_simp 预处理）。

    -- 最经典的应用：平方差公式
example (a b : ℝ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring

-- 展开乘积
example (x y : ℤ) : (x + y) ^ 2 = x ^ 2 + 2 * x * y + y ^ 2 := by ring

-- 验证代数恒等式
example (a b c : ℝ) : (a + b + c) ^ 2 = a^2 + b^2 + c^2 + 2*a*b + 2*b*c + 2*a*c := by ring

-- ring 在 ℕ 上无法处理减法（因为 ℕ 中减法是截断减法）
-- 以下在 ℕ 上会失败，需转换到 ℤ
-- example (a b : ℕ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring  -- 失败
example (a b : ℤ) : (a - b) * (a + b) = a ^ 2 - b ^ 2 := by ring  -- 成功

    norm_num — 对具体数值的命题进行计算验证。可以判断数的大小比较、整除性、素数判定、平方根等涉及具体数字的命题。

    -- 数值等式
example : (2 : ℝ) + 3 = 5 := by norm_num

-- 不等式
example : (7 : ℝ) > 3 := by norm_num

-- 整除性
example : (6 : ℤ) ∣ 42 := by norm_num

-- 素数判定
example : Nat.Prime 997 := by norm_num

-- 证明某数不是素数（1001 = 7 × 11 × 13）
example : ¬ Nat.Prime 1001 := by norm_num

-- 分数计算
example : (1 : ℚ) / 3 + 1 / 6 = 1 / 2 := by norm_num

-- 大数计算（norm_num 使用高效算法）
example : (2 : ℕ) ^ 31 - 1 = 2147483647 := by norm_num

    omega — 解决线性整数/自然数算术问题（Presburger arithmetic 的决策过程）。可处理含有 +、-、数字常数的等式和不等式，但不能处理乘法（变量相乘）。

    -- 基本线性算术
example (n : ℕ) : n + 1 > n := by omega

-- 整除相关（通过余数表达）
example (n : ℕ) (h : n % 2 = 0) : (n + 2) % 2 = 0 := by omega

-- 多个变量的线性关系
example (a b : ℤ) (h1 : a ≤ b) (h2 : b ≤ a + 3) : b - a ≤ 3 := by omega

-- 涉及自然数的界
example (n : ℕ) (h : n < 10) : n ≤ 9 := by omega

-- 绝对值不等式（通过分类讨论展开后使用 omega）
example (a b : ℤ) (h : a + b = 0) : a = -b := by omega

    linarith — 通过线性算术的 Farkas 引理证明线性不等式。与 omega 不同，linarith 可以处理实数（以及任意有序域），并能利用上下文中的假设进行组合推导。

    -- 利用假设的传递性
example (a b c : ℝ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by linarith

-- 组合多个不等式
example (x y : ℝ) (h1 : x ≥ 0) (h2 : y ≥ 0) (h3 : x + y = 1) : x ≤ 1 := by linarith

-- 通过线性组合得到矛盾
example (a b : ℝ) (h1 : a > b) (h2 : b > a) : False := by linarith

-- 配合 have 使用
example (n : ℝ) (h : n > 2) : n ^ 2 > 4 := by
  have h2 : n > 0 := by linarith
  nlinarith [sq_nonneg (n - 2)]

    nlinarith — linarith 的非线性扩展，可处理含有乘积项的不等式。通常需要提供 hint（非负项的平方）来帮助求解器。

    -- AM-GM 不等式：a² + b² ≥ 2ab
example (a b : ℝ) : a ^ 2 + b ^ 2 ≥ 2 * a * b := by
  nlinarith [sq_nonneg (a - b)]
  -- 提示：(a-b)² ≥ 0，展开后正好给出所需结论

-- 带平方的不等式
example (x : ℝ) (h : x > 0) : x + 1 / x ≥ 2 := by
  have h1 : x > 0 := h
  have h2 : (x - 1) ^ 2 ≥ 0 := sq_nonneg _
  nlinarith [mul_pos h1 h1]

-- 多个 hint
example (a b c : ℝ) (ha : a ≥ 0) (hb : b ≥ 0) (hc : c ≥ 0) :
    a * b + b * c + a * c ≤ a ^ 2 + b ^ 2 + c ^ 2 := by
  nlinarith [sq_nonneg (a - b), sq_nonneg (b - c), sq_nonneg (a - c)]

    decide — 对可判定命题（Decidable）进行机械验证。适用于有限域上的命题，如小范围内的全称命题、具体的 Prop 计算。

    -- 直接验证小素数
example : Nat.Prime 7 := by decide

-- 有限集合上的全称命题
example : ∀ n : Fin 5, n.val < 5 := by decide

-- 布尔等式
example : (true && false) = false := by decide

-- 小范围内的整除判断
example : 3 ∣ 12 := by decide

-- 注意：decide 对大数会超时，此时用 native_decide（JIT 编译求值）
example : Nat.Prime 65537 := by native_decide

    5.2 逻辑推导类

    exact h — 当上下文中某个假设或引理 h 精确匹配当前目标时，用 exact h 关闭目标。是最基本的策略。

    example (P : Prop) (h : P) : P := by exact h

-- exact 也可以接受复杂表达式
example (a b : ℕ) (h : a = b) : b = a := by exact h.symm

-- exact 配合引理应用
example (n : ℕ) : n ≤ n := by exact Nat.le_refl n

    intro h — 将目标 P → Q 中的前提 P 引入为假设 h，新目标变为 Q。对全称命题 ∀ x, P x，intro x 引入一个任意变量。

    -- 引入蕴含的前提
example (P Q : Prop) : P → P := by
  intro h  -- h : P，目标变为 P
  exact h

-- 引入多个变量/假设
example (a b c : ℝ) : a ≤ b → b ≤ c → a ≤ c := by
  intro h1 h2  -- 一次引入两个
  linarith

-- 引入全称量化变量
example : ∀ (n : ℕ), n + 0 = n := by
  intro n  -- n 成为任意自然数
  exact Nat.add_zero n

-- intro 可以解构模式（同时引入并析构）
example (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro ⟨hp, hq⟩  -- 直接析构合取
  exact ⟨hq, hp⟩

    apply h — 向后推理：如果 h : A → B（或更一般的 A₁ → A₂ → ... → B），且当前目标是 B，则 apply h 将目标变为 A（或多个子目标）。

    -- 基本 apply
example (P Q : Prop) (hpq : P → Q) (hp : P) : Q := by
  apply hpq  -- 目标变为 P
  exact hp

-- apply 引理
example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  apply Nat.le_trans h1  -- 应用传递性，目标变为 b ≤ c
  exact h2

-- apply 产生多个子目标
example (n : ℕ) : 0 < n + 1 := by
  apply Nat.succ_pos  -- 立即完成

    assumption — 自动搜索上下文中与当前目标完全匹配的假设。比 exact 更懒惰但更方便。

    example (P Q R : Prop) (hp : P) (hq : Q) (hr : R) : Q := by
  assumption  -- 自动找到 hq : Q

-- 常用于多分支证明的叶节点
example (P Q : Prop) (h : P ∧ Q) : P := by
  obtain ⟨hp, _⟩ := h
  assumption

    constructor — 将目标分裂为其构造子的分量。对合取（P ∧ Q）产生两个子目标 P 和 Q；对存在命题（∃ x, P x）需要提供 witness。

    -- 证明合取
example (n : ℕ) : n ≤ n + 1 ∧ n < n + 2 := by
  constructor
  · linarith  -- 第一个分量
  · linarith  -- 第二个分量

-- 证明双向蕴含（Iff）
example (n : ℕ) : n = 0 ↔ n < 1 := by
  constructor
  · intro h; omega
  · intro h; omega

    left / right — 选择析取（P ∨ Q）的左支或右支。

    -- 选择左支
example : 1 = 1 ∨ 1 = 2 := by
  left; rfl

-- 根据条件选择
example (n : ℕ) (h : n = 0 ∨ n > 0) : n = 0 ∨ n ≥ 0 := by
  cases h with
  | inl h0 => left; exact h0
  | inr hpos => right; linarith

    exfalso — 将当前目标替换为 False。用于"从矛盾推出任意结论"的场景，通常配合矛盾的假设使用。

    -- 从矛盾假设证明任意命题
example (P : Prop) (h1 : P) (h2 : ¬P) : 0 = 1 := by
  exfalso
  exact h2 h1  -- 现在目标是 False，用 h2 h1 : False

-- 配合 linarith 使用
example (n : ℕ) (h1 : n > 5) (h2 : n < 3) : False := by
  linarith  -- 直接从假设的矛盾关闭目标（linarith 也可直接证明 False）

    5.3 否定与反证类

    push_neg — 将否定符号向内推，应用德摩根定律和量词否定规则。把 ¬∀ x, P x 变为 ∃ x, ¬P x，把 ¬(P ∧ Q) 变为 P → ¬Q 等。

    -- 否定全称命题
example : ¬ (∀ n : ℕ, n < 10) := by
  push_neg          -- 目标变为 ∃ n, 10 ≤ n
  exact ⟨10, le_refl 10⟩

-- 否定蕴含
example (P Q : Prop) (h : ¬(P → Q)) : P ∧ ¬Q := by
  push_neg at h  -- h 变为 P ∧ ¬Q（将 push_neg 作用于假设）
  exact h

-- 连续否定
example : ¬ (∀ x : ℝ, ∃ y : ℝ, y > x) := by
  push_neg   -- 目标变为 ∃ x, ∀ y, y ≤ x（有上界）
  -- 但这个命题是假的，所以这个例子是无法完成的
  sorry

    contrapose — 将目标 P → Q 转化为逆否命题 ¬Q → ¬P。有时逆否方向更容易证明。

    -- 证明：若 n² 为奇数，则 n 为奇数（逆否：n 为偶数 → n² 为偶数）
theorem odd_sq_imp_odd (n : ℤ) (h : ¬ 2 ∣ n ^ 2) : ¬ 2 ∣ n := by
  contrapose! h   -- 目标变为：2 ∣ n → 2 ∣ n²（contrapose! 同时 push_neg）
  intro ⟨k, hk⟩
  exact ⟨2 * k ^ 2, by rw [hk]; ring⟩

-- 基本 contrapose（不 push_neg）
example (P Q : Prop) : (P → Q) → (¬Q → ¬P) := by
  intro hpq hnq hp
  exact hnq (hpq hp)

    by_contra h — 假设目标的否定并命名为 h，进行反证。目标变为 False。

    -- 反证法：证明素数有无穷多个（简化版）
-- 若只有有限多个素数，则其乘积+1不被任何已知素数整除，矛盾
-- 这里演示反证法的结构
example (P : Prop) : ¬¬P → P := by
  intro hnnp
  by_contra hnp  -- 假设 ¬P，目标变为 False
  exact hnnp hnp  -- ¬¬P 应用于 ¬P 得 False

-- 更实际的例子
theorem sqrt2_irrational_sketch : ¬ ∃ (p q : ℕ), q ≠ 0 ∧
    Nat.Coprime p q ∧ (p : ℝ)^2 = 2 * q^2 := by
  intro ⟨p, q, hq, hcop, heq⟩
  -- 这里会涉及复杂推导，用 sorry 展示结构
  sorry

    5.4 结构析构类

    obtain — 析构存在命题或合取命题，将其分量引入上下文。是 rcases 的常用别名。

    -- 析构存在命题 ∃ x, P x
example (h : ∃ n : ℕ, n > 5) : ∃ m : ℕ, m > 3 := by
  obtain ⟨n, hn⟩ := h  -- 引入 n : ℕ 和 hn : n > 5
  exact ⟨n, by linarith⟩

-- 析构合取 P ∧ Q
example (h : (1 : ℕ) < 2 ∧ 2 < 3) : (1 : ℕ) < 3 := by
  obtain ⟨h1, h2⟩ := h  -- h1 : 1 < 2, h2 : 2 < 3
  linarith

-- 嵌套析构
example (h : ∃ n : ℕ, n > 0 ∧ n < 5) : ∃ m : ℕ, m < 10 := by
  obtain ⟨n, hpos, hlt⟩ := h
  exact ⟨n, by linarith⟩

    cases h — 对归纳类型按构造子分类讨论。对 h : P ∨ Q 产生两个分支；对 h : ℕ 产生 zero 和 succ 两个分支。

    -- 对析取分类
example (h : 2 ∣ n ∨ 2 ∣ (n + 1)) : 2 ∣ n * (n + 1) := by
  cases h with
  | inl h2n => exact Dvd.dvd.mul_right h2n _
  | inr h2n1 => exact Dvd.dvd.mul_left h2n1 _

-- 对自然数分类（零和后继）
example (n : ℕ) : n = 0 ∨ ∃ m, n = m + 1 := by
  cases n with
  | zero => left; rfl
  | succ m => right; exact ⟨m, rfl⟩

-- 对 Option 分类
example (x : Option ℕ) : x = none ∨ ∃ n, x = some n := by
  cases x with
  | none => left; rfl
  | some n => right; exact ⟨n, rfl⟩

    rcases — 递归案例分析，支持复杂的嵌套模式。比 cases 更灵活，可以一次性析构多层结构。

    -- 析构嵌套存在
example (h : ∃ a b : ℕ, a + b = 10) : ∃ n : ℕ, n ≤ 10 := by
  rcases h with ⟨a, b, hab⟩
  exact ⟨a, by omega⟩

-- 析构析取的每个分支
example (h : (n : ℤ) = 2 * k ∨ n = 2 * k + 1) : True := by
  rcases h with heven | hodd <;> trivial

-- 复杂嵌套模式
example (h : ∃ x : ℕ, x > 0 ∧ (x = 1 ∨ x = 2)) : True := by
  rcases h with ⟨x, hx, h1 | h2⟩ <;> trivial

    use t — 为存在命题 ∃ x, P x 提供 witness t，目标变为 P t。

    -- 提供具体的 witness
example : ∃ n : ℕ, n * n = 25 := by
  use 5  -- 目标变为 5 * 5 = 25
  norm_num

-- 提供表达式作为 witness
example (n : ℕ) : ∃ m : ℕ, m = n + 1 := by
  use n + 1  -- 目标变为 n + 1 = n + 1
  rfl

-- 多个 use（同时提供多个 witness 和条件）
example : ∃ a b : ℕ, a + b = 7 ∧ a < b := by
  use 3, 4
  norm_num

    5.5 归纳与递归

    induction — 对归纳类型应用归纳原理。Lean 4 的新语法使用 with 关键字分支。

    -- 自然数归纳：证明前 n 个自然数之和 = n*(n+1)/2
-- 等价形式：2 * ∑ k in Finset.range (n+1), k = n * (n+1)
theorem sum_range_eq (n : ℕ) :
    2 * ∑ k ∈ Finset.range (n + 1), k = n * (n + 1) := by
  induction n with
  | zero =>
    simp  -- 基础情形：n = 0，等式两侧均为 0
  | succ n ih =>
    -- 归纳步骤：假设对 n 成立（ih），证明对 n+1 成立
    rw [Finset.sum_range_succ]
    linarith

-- 更简单的例子：证明偶数的归纳定义
theorem even_add_two (n : ℕ) (h : 2 ∣ n) : 2 ∣ n + 2 := by
  obtain ⟨k, hk⟩ := h
  exact ⟨k + 1, by omega⟩

-- 强归纳（Strong Induction）
theorem divides_factorial (n k : ℕ) (h : 1 ≤ k) (hk : k ≤ n) : k ∣ n.factorial := by
  exact Nat.factorial_dvd_factorial_of_le hk |>.symm ▸ sorry

    refine — 提供部分证明项，用 ?_ 或命名占位符标记未完成的子目标。适合自顶向下构造证明。

    -- refine 构造合取
example (n : ℕ) : n ≤ n + 1 ∧ n < n + 2 := by
  refine ⟨?_, ?_⟩  -- 产生两个子目标
  · omega
  · omega

-- refine 配合引理
example (a b c : ℕ) (h1 : a ≤ b) (h2 : b ≤ c) : a ≤ c := by
  refine Nat.le_trans ?_ h2  -- 第一个参数未填
  exact h1

-- refine 中命名占位符
example : ∃ n : ℕ, n > 100 ∧ Nat.Prime n := by
  refine ⟨101, ?gt, ?prime⟩
  case gt => norm_num
  case prime => norm_num

    5.6 化简与搜索

    simp — 利用等式引理库进行重写和化简。是最强大也最需要谨慎使用的策略之一。可以指定额外的引理，也可以用 simp only 限制使用的引理集。

    -- 基本化简
example (n : ℕ) : n + 0 = n := by simp

-- 利用指定引理化简
example (a b : ℝ) (ha : a > 0) : |a| = a := by
  simp [abs_of_pos ha]

-- simp only（只用指定引理，避免意外化简）
example (n m : ℕ) : n + m = m + n := by
  simp only [Nat.add_comm]

-- simp 作用于假设
example (h : n + 0 = 5) : n = 5 := by
  simp at h  -- h 变为 n = 5
  exact h

-- simp 配合 [*]（使用所有假设作为引理）
example (a b : ℕ) (ha : a = 3) (hb : b = 4) : a + b = 7 := by
  simp [ha, hb]

    simp? — 执行 simp 并在 Infoview 中显示实际使用的引理列表，方便之后改用 simp only 加速。

    -- simp? 会在 Infoview 中建议：
-- Try this: simp only [Nat.add_zero, Nat.zero_add, ...]
example (n : ℕ) : n + 0 + 0 = n := by simp?

    exact? — 在 Mathlib 中搜索能直接关闭当前目标的引理，并在 Infoview 中显示建议。这是发现引理名称最高效的方法。

    -- 使用 exact? 时，将光标放在 exact? 上，
-- Infoview 会显示类似：
-- Try this: exact Nat.le_refl n
example (n : ℕ) : n ≤ n := by exact?

-- exact? 发现的引理可以替换 exact? 本身
example (a b : ℤ) (h : a ∣ b) : a ∣ b * 2 := by exact?
-- 可能建议：exact h.mul_right 2

    apply? — 搜索能将当前目标规约为更简单目标的引理。返回可用引理列表，需要人工判断选择。

    -- apply? 会建议可以 apply 的引理
example (a b c : ℕ) : a + b + c = c + b + a := by
  apply?  -- 可能建议 Nat.add_comm, Nat.add_assoc 的组合

    norm_cast / push_cast — 处理不同数字类型之间的强制转换（coercion），消除 (↑n : ℝ) 类型的类型转换符号，使跨类型等式和不等式可以用其他策略处理。

    -- 混合 ℕ 和 ℝ 的等式
example (n : ℕ) : (n : ℝ) + 1 = (n + 1 : ℕ) := by norm_cast

-- push_cast 将 cast 向内推
example (a b : ℕ) : (a + b : ℝ) = (a : ℝ) + (b : ℝ) := by push_cast; ring

-- 常见场景：ℕ 和 ℤ 混用
example (n : ℕ) (h : (n : ℤ) > 0) : n > 0 := by exact_mod_cast h

-- norm_cast 处理含有 cast 的等式
example (n m : ℕ) (h : (n : ℤ) = (m : ℤ)) : n = m := by exact_mod_cast h

    6. Mathlib 命名惯例

    Mathlib4 有超过 18 万条引理，掌握其命名规律是高效使用的关键。不需要记住引理名，但需要能够猜测引理名或有效搜索。

    6.1 命名空间结构

    Mathlib 按数学结构组织命名空间，常见的有：

    • Nat. — 自然数（ℕ）相关引理
    • Int. — 整数（ℤ）相关引理
    • Real. — 实数（ℝ）相关引理
    • Rat. — 有理数（ℚ）相关引理
    • Finset. — 有限集合引理
    • List. — 列表相关引理
    • Polynomial. — 多项式引理
    • Matrix. — 矩阵引理
    • Complex. — 复数引理

    6.2 命名模式

    Mathlib 引理名遵循几个核心模式：

    -- 模式一：属性_of_条件
-- "从条件得到属性"
#check Nat.lt_of_add_lt_add_left  -- a + b < a + c → b < c
#check Int.pos_of_ne_zero_of_nonneg  -- n ≠ 0 → 0 ≤ n → 0 < n

-- 模式二：对象.操作_目标
-- "对象的操作关于目标成立"
#check Nat.add_comm    -- n + m = m + n
#check Nat.mul_comm    -- n * m = m * n
#check Int.add_comm    -- n + m = m + n（ℤ 上）

-- 模式三：属性_属性（两个属性的关系）
#check Nat.even_add_odd   -- even n → odd m → odd (n + m)
#check Int.even_mul_succ_self  -- 2 ∣ n * (n + 1)

-- 模式四：Finset 操作
#check Finset.sum_add_distrib  -- ∑ i, (f i + g i) = ∑ i, f i + ∑ i, g i
#check Finset.prod_congr       -- 集合相等时乘积相等

-- 模式五：实分析
#check Real.sqrt_sq    -- 0 ≤ x → √(x²) = x
#check Real.sq_sqrt    -- 0 ≤ x → (√x)² = x
#check Real.log_mul    -- x > 0 → y > 0 → log(xy) = log x + log y

    6.3 后缀惯例

    -- _iff：当且仅当形式（最通用）
#check Nat.lt_iff_add_one_le  -- n < m ↔ n + 1 ≤ m

-- _eq：等式形式
#check Nat.succ_eq_add_one    -- n.succ = n + 1

-- _le：小于等于
#check Nat.le_add_left        -- n ≤ m + n

-- _lt：严格小于
#check Nat.lt_add_one         -- n < n + 1

-- _pos：正数条件
#check Nat.pos_of_ne_zero     -- n ≠ 0 → 0 < n

-- _nonneg：非负条件
#check Int.natAbs_nonneg      -- 0 ≤ n.natAbs（实际是 ℕ，永远成立）
#check sq_nonneg              -- 0 ≤ x ^ 2

-- _comm：交换律
-- _assoc：结合律
-- _distrib：分配律
#check mul_add   -- a * (b + c) = a * b + a * c（左分配）
#check add_mul   -- (a + b) * c = a * c + b * c（右分配）

    在实际工作中，以下几种方法可以帮助找到所需引理：

    • simp? — 让 simp 告诉你它用了哪些引理

    7. 竞赛数学形式化模式

    基于形式化 18 道 ICCM 题的经验，以下总结了各类题型的典型形式化模式和常用策略组合。

    7.1 代数恒等式

    代数恒等式是最容易形式化的类型。ring 能自动处理绝大多数多项式恒等式；若涉及分式，先用 field_simp 清除分母，再用 ring。

    -- 平方和公式：(a + b)² = a² + 2ab + b²
theorem sq_expand (a b : ℝ) : (a + b)^2 = a^2 + 2*a*b + b^2 := by ring

-- 立方差公式：a³ - b³ = (a-b)(a² + ab + b²)
theorem cube_diff (a b : ℝ) : a^3 - b^3 = (a - b) * (a^2 + a*b + b^2) := by ring

-- 多变量恒等式
theorem three_var_identity (a b c : ℝ) :
    (a + b + c)^2 = a^2 + b^2 + c^2 + 2*(a*b + b*c + a*c) := by ring

-- Vieta 关系（用于多项式根）
theorem vieta_check (p q r : ℝ) :
    (p + q + r) * (p*q + q*r + p*r) - p*q*r =
    p^2*q + p^2*r + q^2*p + q^2*r + r^2*p + r^2*q := by ring

-- 分式恒等式（先 field_simp 再 ring）
theorem frac_identity (a b : ℝ) (ha : a ≠ 0) (hb : b ≠ 0) :
    1/a + 1/b = (a + b) / (a * b) := by
  field_simp
  ring

    7.2 整数与整除

    整除性证明经常需要的工具：dvd_intro（提供 witness）、Nat.dvd_add（整除的加法性质）、omega（余数算术）。对于 mod 运算，Int.emod_emod_of_dvd 很有用。

    -- n(n+1)(n+2) 被 6 整除
-- 策略：利用 n, n+1, n+2 中必有一个是 2 的倍数，一个是 3 的倍数
theorem six_dvd_consec_prod (n : ℤ) : 6 ∣ n * (n + 1) * (n + 2) := by
  have h2 : 2 ∣ n * (n + 1) * (n + 2) := by
    have := Int.even_mul_succ_self n  -- 2 ∣ n*(n+1)
    exact this.mul_right (n + 2)
  have h3 : 3 ∣ n * (n + 1) * (n + 2) := by
    have := Int.three_dvd_iff_sum_digits -- 这个引理可能不存在，用 omega/rcases 代替
    omega
  sorry -- 完整证明需要 Int.Coprime → dvd 乘积

-- 更简单的整除例子：n(n+1) 被 2 整除
theorem two_dvd_n_mul_succ (n : ℤ) : 2 ∣ n * (n + 1) := by
  rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
  · -- n 是偶数
    exact ⟨k * (n + 1), by rw [hk]; ring⟩
  · -- n 是奇数（n+1 是偶数）
    exact ⟨n * (k + 1), by rw [hk]; ring⟩

-- 使用 omega 的整除例子
theorem dvd_by_omega_example (n : ℤ) : 2 ∣ n^2 + n := by
  have factored : n^2 + n = n * (n + 1) := by ring
  rw [factored]
  exact two_dvd_n_mul_succ n

-- Nat 的整除
theorem nat_dvd_example : 12 ∣ 3 * 4 * 5 - 3 * 4 := by norm_num

-- 使用 dvd_trans
theorem dvd_trans_example (a b c : ℤ) (h1 : a ∣ b) (h2 : b ∣ c) : a ∣ c :=
  dvd_trans h1 h2

    7.3 不等式

    竞赛不等式通常需要 AM-GM、Cauchy-Schwarz 等经典不等式作为引理，或者通过 SOS（平方和）分解后用 nlinarith 关闭。

    -- AM-GM：a² + b² ≥ 2ab
theorem am_gm_sq (a b : ℝ) : a^2 + b^2 ≥ 2 * a * b := by
  nlinarith [sq_nonneg (a - b)]

-- 更一般的 AM-GM（两个正数）
theorem am_gm_pos (a b : ℝ) (ha : a > 0) (hb : b > 0) : a + b ≥ 2 * Real.sqrt (a * b) := by
  sorry -- 需要 Real.sqrt 的相关引理，这里展示结构

-- Cauchy-Schwarz（有限和版本）
-- (∑ a_i b_i)² ≤ (∑ a_i²) * (∑ b_i²)
-- Mathlib 中已有：inner_mul_le_norm_mul_norm

-- 三角不等式
theorem triangle_ineq_sq (a b c : ℝ) (ha : 0 < a) (hb : 0 < b) (hc : 0 < c)
    (h : a + b > c) (h2 : b + c > a) (h3 : a + c > b) :
    a^2 + b^2 + c^2 < (a + b + c)^2 / 2 + (a*b + b*c + a*c) := by
  nlinarith [sq_nonneg (a - b), sq_nonneg (b - c), sq_nonneg (a - c)]

-- 基本不等式组合
theorem ineq_combination (x y z : ℝ) (hx : x ≥ 0) (hy : y ≥ 0) (hz : z ≥ 0)
    (hxyz : x + y + z = 1) : x*y + y*z + x*z ≤ 1/3 := by
  nlinarith [sq_nonneg (x - y), sq_nonneg (y - z), sq_nonneg (x - z)]

    7.4 存在性与构造性证明

    存在性证明通常需要给出明确的 witness，然后验证它满足条件。有时需要分情况讨论来确定 witness 的具体形式。

    -- 简单存在性：存在一个大于 100 的偶数
theorem exists_even_gt_100 : ∃ n : ℕ, n > 100 ∧ 2 ∣ n := by
  use 102
  norm_num

-- 参数化存在性：对任意 n，存在比 n 大的素数
-- （Mathlib 中已有 Nat.exists_infinite_primes）
theorem exists_prime_gt (n : ℕ) : ∃ p : ℕ, p > n ∧ Nat.Prime p :=
  Nat.exists_infinite_primes (n + 1) |>.imp fun p ⟨hp_ge, hp_prime⟩ =>
    ⟨Nat.lt_of_succ_le hp_ge, hp_prime⟩

-- 利用整除构造 witness
theorem exists_multiple (n k : ℤ) (hk : k ≠ 0) (h : k ∣ n) :
    ∃ m : ℤ, n = k * m := by
  exact h  -- ∣ 的定义就是存在这样的 m

-- 构造性证明：二次方程有理根的存在条件
-- 若 a, b, c ∈ ℤ 且 b² - 4ac = d² 对某整数 d 成立，则方程有有理根
theorem rational_root_exists (a b c d : ℤ) (ha : a ≠ 0)
    (h : b^2 - 4*a*c = d^2) :
    ∃ p q : ℤ, q ≠ 0 ∧ a * p^2 + b * p * q + c * q^2 = 0 := by
  use -b + d, 2 * a
  constructor
  · intro h2a; exact ha (by linarith [h2a])
  · nlinarith [sq_nonneg d]

    7.5 归纳证明

    数学归纳法在 Lean 4 中通过 induction 策略实现。关键是正确识别归纳假设（ih）并在归纳步骤中使用它。

    -- 经典归纳：∑_{k=0}^{n} k = n(n+1)/2
-- Lean 4 中用 2 * sum = n*(n+1) 避免分数
theorem gauss_sum (n : ℕ) :
    2 * ∑ k ∈ Finset.range (n + 1), k = n * (n + 1) := by
  induction n with
  | zero => simp
  | succ n ih =>
    rw [Finset.sum_range_succ]
    push_cast
    linarith

-- 归纳：整除性质
-- 3 | 4^n - 1 对所有 n : ℕ
theorem three_dvd_pow4_sub1 (n : ℕ) : 3 ∣ 4^n - 1 := by
  induction n with
  | zero => simp
  | succ n ih =>
    have : (4 : ℤ)^(n + 1) - 1 = 4 * (4^n - 1) + 3 := by ring
    -- 需要先转到 ℤ 以避免 ℕ 减法截断问题
    sorry

-- ℤ 上的归纳版本
theorem three_dvd_pow4_sub1' (n : ℕ) : (3 : ℤ) ∣ 4^n - 1 := by
  induction n with
  | zero => norm_num
  | succ n ih =>
    have key : (4 : ℤ)^(n + 1) - 1 = 4 * (4^n - 1) + 3 := by ring
    rw [key]
    exact dvd_add (dvd_mul_of_dvd_right ih 4) (dvd_refl 3)

-- 强归纳：fibonacci 性质
-- 略去，展示结构
theorem fib_property (n : ℕ) : True := by
  induction n using Nat.strong_induction_on with
  | _ n ih => trivial

    8. 完整例子——从纸面到 Lean

    这一节演示将一道具体题目从直觉证明转化为完整 Lean 4 代码的完整过程，包括犯错和修正。

    8.1 例题一：(a+b)² ≡ a² + b² (mod 2)

    题目：对任意整数 a, b，证明 (a+b)² ≡ a² + b² (mod 2)。

    纸面分析：(a+b)² = a² + 2ab + b²，所以 (a+b)² - (a² + b²) = 2ab，这是 2 的倍数，所以 (a+b)² 和 a² + b² 模 2 同余。

    第一步：用 sorry 写出框架。

    -- 先建立命题，暂不证明
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  sorry  -- 占位，先看命题是否表述正确

    第二步：考虑证明策略。关键等式是 (a+b)² - (a² + b²) = 2ab。在 ℤ 上，omega 能处理线性整数算术，但 (a+b)² 展开涉及乘法，需要先用 ring 或 have 化简。

    -- 第二步：添加关键 have
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  have h : (a + b)^2 - (a^2 + b^2) = 2 * (a * b) := by ring
  -- 现在 h 告诉我们差是 2 的倍数
  -- omega 可以处理：如果 x - y = 2 * k，则 x % 2 = y % 2
  omega

    这个证明已经正确！ring 建立代数等式，omega 处理模运算的线性部分。注意 omega 接受上下文中的所有整数等式/不等式，包括 h，所以能推出目标。

    清洁版本：

    import Mathlib

-- 最终版本
theorem sq_sum_mod2 (a b : ℤ) : (a + b)^2 % 2 = (a^2 + b^2) % 2 := by
  have h : (a + b)^2 - (a^2 + b^2) = 2 * (a * b) := by ring
  omega

    8.2 例题二：n² + n 恒为偶数

    题目：对任意整数 n，证明 2 ∣ n² + n。

    纸面分析：n² + n = n(n+1)，n 和 n+1 是连续整数，其中必有一个是偶数，故乘积是偶数。

    错误的第一次尝试：

    -- 错误尝试：直接提供 witness（但 witness 本身不是整数！）
theorem n_sq_plus_n_even_wrong (n : ℤ) : 2 ∣ n^2 + n := by
  use n * (n + 1) / 2  -- 错误！ℤ 的除法不是精确的，这会截断
  ring  -- 会失败，因为 ring 无法处理整数除法

    正确方法一：用分情况讨论（n 为偶数或奇数）

    theorem n_sq_plus_n_even (n : ℤ) : 2 ∣ n^2 + n := by
  have factored : n^2 + n = n * (n + 1) := by ring
  rw [factored]
  -- 现在需要证明 2 ∣ n * (n + 1)
  rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
  · -- n 是偶数：n = 2k
    exact ⟨k * (n + 1), by rw [hk]; ring⟩
  · -- n 是奇数：n = 2k + 1，所以 n + 1 = 2k + 2 = 2(k+1)
    exact ⟨n * (k + 1), by rw [hk]; ring⟩

    正确方法二：用 omega（更简洁）

    -- omega 可以直接处理！因为 n^2 + n = n*(n+1)，而 2 ∣ n*(n+1)
-- 实际上 omega 处理线性整数，但 2 ∣ n^2 + n 经过化简后可以 omega 处理
theorem n_sq_plus_n_even' (n : ℤ) : 2 ∣ n^2 + n := by
  have : n^2 + n = n * (n + 1) := by ring
  rw [this]
  have : 2 ∣ n * (n + 1) := by
    rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
    · exact ⟨k * (n + 1), by linarith [hk]⟩
    · exact ⟨n * (k + 1), by linarith [hk]⟩
  exact this

    8.3 例题三：完整的归纳证明

    题目：证明对所有自然数 n，有 3 ∣ n³ - n（即 n³ ≡ n (mod 3)）。

    -- 方法一：代数因式分解
-- n³ - n = n(n-1)(n+1) = (n-1)n(n+1)，三个连续整数之积
theorem three_dvd_cube_minus (n : ℤ) : 3 ∣ n^3 - n := by
  have factored : n^3 - n = (n - 1) * n * (n + 1) := by ring
  rw [factored]
  -- 三个连续整数中必有一个是 3 的倍数
  -- 按 n mod 3 分类
  have hmod : n % 3 = 0 ∨ n % 3 = 1 ∨ n % 3 = 2 := by omega
  rcases hmod with h0 | h1 | h2
  · -- 3 ∣ n
    have hn : 3 ∣ n := ⟨n / 3, by omega⟩
    exact dvd_mul_of_dvd_right (dvd_mul_of_dvd_right hn _) _
  · -- 3 ∣ n - 1（即 n ≡ 1 mod 3，所以 n - 1 ≡ 0 mod 3）
    have hn1 : 3 ∣ n - 1 := ⟨(n - 1) / 3, by omega⟩
    exact dvd_mul_of_dvd_left (dvd_mul_of_dvd_left hn1 _) _
  · -- 3 ∣ n + 1（n ≡ 2 ≡ -1 mod 3）
    have hn1 : 3 ∣ n + 1 := ⟨(n + 1) / 3, by omega⟩
    exact dvd_mul_of_dvd_right (dvd_mul_of_dvd_left hn1 _) _

-- 方法二：归纳法
theorem three_dvd_cube_minus_induction (n : ℤ) : 3 ∣ n^3 - n := by
  have : n^3 - n = n * (n - 1) * (n + 1) := by ring
  rw [this]
  omega  -- omega 直接完成！（能处理三个连续数之积被 3 整除）

    注意方法二中 omega 直接完成了关于连续整数乘积被 3 整除的推理，这是 Lean 4 中 omega 强大之处。

    9. 常见错误与排错

    9.1 ℕ 减法截断

    这是初学者最常遇到的陷阱。在 Lean 4 中，ℕ（自然数）的减法是截断减法：3 - 5 = 0 而不是 -2。这与数学直觉不符，会导致莫名其妙的证明失败。

    -- 问题示例
#eval (3 : ℕ) - 5    -- 输出 0，不是 -2！

-- 以下证明会失败，因为 ℕ 中 a - b 的含义不是我们想要的
-- example (a b : ℕ) (h : a ≥ b) : (a - b) + b = a := by ring  -- ring 失败

-- 正确做法：在 ℤ 上工作，或使用 Nat.sub_add_cancel
example (a b : ℕ) (h : b ≤ a) : a - b + b = a := Nat.sub_add_cancel h

-- 如果需要负数，转换到 ℤ
example (a b : ℤ) : (a - b) + b = a := by ring  -- 在 ℤ 上 ring 正常工作

-- 强制转换 ℕ 到 ℤ
example (n m : ℕ) (h : n ≤ m) : (n : ℤ) - m ≤ 0 := by
  have : (n : ℤ) ≤ (m : ℤ) := Int.ofNat_le.mpr h
  linarith

    9.2 类型不匹配

    Lean 4 是强类型系统，ℕ、ℤ、ℚ、ℝ 是不同的类型，混用会报错。错误信息通常是 type mismatch: expected ℝ, got ℕ。

    -- 类型不匹配示例
-- example (n : ℕ) (x : ℝ) : n + x = x + n := by ring  -- 失败！

-- 解决方法：显式转换
example (n : ℕ) (x : ℝ) : (n : ℝ) + x = x + (n : ℝ) := by ring

-- norm_cast 处理转换
example (n m : ℕ) (h : n < m) : (n : ℝ) < (m : ℝ) := by exact_mod_cast h

-- push_cast 将转换推入表达式内部
example (n m : ℕ) : ((n + m : ℕ) : ℝ) = (n : ℝ) + (m : ℝ) := by push_cast; ring

-- 常见模式：在 ℕ 上推导，需要 ℝ 的不等式
example (n : ℕ) (h : n > 0) : (n : ℝ) > 0 := by exact Nat.cast_pos.mpr h

    9.3 omega 不处理乘法

    omega 只处理线性整数算术，遇到变量乘法会报错或无法完成。

    -- omega 失败的例子
-- example (n : ℤ) : n^2 ≥ 0 := by omega  -- 失败！n^2 是非线性的

-- 正确：用 sq_nonneg
example (n : ℤ) : n^2 ≥ 0 := sq_nonneg n

-- 另一个失败例子：
-- example (a b : ℤ) : a * b = b * a := by omega  -- 失败

-- 正确：用 ring（乘法交换律）
example (a b : ℤ) : a * b = b * a := by ring

-- omega 和 nlinarith 的配合
-- 先用 ring 化简为线性形式，再用 omega
example (n : ℤ) : n^2 + 2*n + 1 = (n + 1)^2 := by ring  -- ring 直接解决

    9.4 ring 在 ℕ 上失败

    ring 处理的是环（ring），而 ℕ 不是环（因为没有加法逆元，即没有减法）。含有减法的等式在 ℕ 上 ring 会失败。

    -- ring 在 ℕ 上失败
-- example (a b : ℕ) : (a + b) - b = a := by ring  -- 失败

-- 解决方法一：转到 ℤ
example (a b : ℕ) : (a : ℤ) + b - b = a := by ring

-- 解决方法二：使用专用引理
example (a b : ℕ) (h : b ≤ a + b) : (a + b) - b = a := Nat.add_sub_cancel

-- 解决方法三：omega（能处理 ℕ 上的部分减法情形）
example (a b : ℕ) (h : b ≤ a) : a - b + b = a := by omega

    9.5 引理名称变更

    Mathlib4 仍在积极开发中，引理名称偶尔会变更。不要硬记引理名，每次使用 exact? 或 apply? 确认。

    -- 不好的做法：硬记可能过时的名字
-- exact Nat.lt_of_sub_eq_succ h  -- 这个名字可能已变更

-- 好的做法：用 exact? 搜索
example (n m : ℕ) (h : n ≤ m) : n < m + 1 := by exact?
-- exact? 会给出当前正确的引理名

-- 另一个好习惯：对于简单关系，直接用策略而不是引理
example (n : ℕ) : n < n + 1 := by omega  -- 不依赖具体引理名

    在完成形式化后，必须确保所有 sorry 都已删除。lake build 会对含有 sorry 的文件发出警告（但不是错误），这在形式化验证工作中是不可接受的。

-- 在终端中运行：
-- grep -r "sorry" *.lean
-- 或者：lake build 2>&1 | grep "sorry"

-- Lean 4 中 sorry 的警告信息形如：

    10. 进阶——自动化战术

    以下是更高级的自动化策略，在 Mathlib4 中可用，能处理许多繁琐但规律性强的证明。

    10.1 aesop

    aesop（Automated Extensional Situation/Object Prover）是 Lean 4 的通用自动化策略，通过规则数据库进行向前/向后搜索。适合结构性证明，如集合操作、逻辑推导等。

    -- aesop 处理集合操作
example (s t : Finset ℕ) (h : s ⊆ t) (x : ℕ) (hx : x ∈ s) : x ∈ t := by
  aesop  -- 或者 exact h hx

-- aesop 处理类型类相关证明
example (α : Type*) (s : Finset α) : s.card ≥ 0 := by aesop

    10.2 positivity

    positivity 专门用于证明某个表达式大于零或非负。它能处理乘积、幂、绝对值、平方根等结构的正性/非负性。

    -- 证明正性
example (a b : ℝ) (ha : 0 < a) (hb : 0 < b) : 0 < a * b := by positivity

-- 证明非负性
example (a : ℝ) : 0 ≤ a ^ 2 := by positivity

-- 复合表达式
example (n : ℕ) (a : ℝ) (ha : 0 < a) : 0 < a ^ n + 1 := by positivity

-- 比 nlinarith 更目标导向
example (x y : ℝ) (hx : 0 < x) (hy : 0 ≤ y) : 0 ≤ x^2 * y + x := by positivity

    10.3 field_simp

    field_simp 在域（field）上清除分母，将含有除法的目标化简为不含分母的形式，然后可以用 ring 完成。使用前需要证明分母非零。

    -- 清除分母后用 ring
example (a b : ℝ) (ha : a ≠ 0) (hb : b ≠ 0) :
    (a + b) / (a * b) = 1/b + 1/a := by
  field_simp
  ring

-- 处理多个分母
example (x y z : ℝ) (hx : x ≠ 0) (hy : y ≠ 0) (hz : z ≠ 0) :
    1/x + 1/y + 1/z = (y*z + x*z + x*y) / (x*y*z) := by
  field_simp
  ring

    10.4 norm_cast 与 exact_mod_cast

    这一组策略专门处理数字类型之间的强制转换。norm_cast 在目标中规范化 cast；exact_mod_cast 和 apply_mod_cast 在提供/应用证明时忽略 cast 差异。

    -- norm_cast 作为策略（关闭含 cast 的目标）
example (n m : ℕ) (h : n ≤ m) : (n : ℤ) ≤ (m : ℤ) := by exact_mod_cast h

-- norm_cast 规范化 cast
example (n : ℕ) : (n : ℝ) + 0 = n := by norm_cast

-- push_cast 将 cast 向内推
example (n m : ℕ) : ((n * m : ℕ) : ℝ) = (n : ℝ) * (m : ℝ) := by push_cast; ring

-- 综合使用
theorem cast_ineq_example (n : ℕ) (h : n > 0) : (n : ℝ) > 0 := by
  exact_mod_cast h

    10.5 decide 与 native_decide

    decide 通过内核运行（kernel evaluation）来验证可判定命题；native_decide 通过 JIT 编译来运行，速度更快，适合大数计算。

    -- decide：适合小范围
example : Nat.Prime 31 := by decide
example : ¬ (4 : ℕ) ∣ 10 := by decide

-- native_decide：适合大数
example : Nat.Prime 65537 := by native_decide  -- 费马数，decide 会很慢
example : (Finset.range 100).card = 100 := by native_decide

-- decide 可以验证有限类型上的全称命题
example : ∀ b : Bool, b || true = true := by decide

-- 有时用 norm_num 比 decide 更快
example : Nat.Prime 1000003 := by norm_num  -- norm_num 对素数判定有优化

    10.6 simp_arith

    simp_arith 是 simp 加上算术规则的组合，可以处理一些 simp 单独无法完成但 omega 也太弱的情形。

    -- simp_arith 处理带有算术的化简
example (n : ℕ) (h : n ≥ 1) : n + n ≥ 2 := by simp_arith
example (n : ℕ) : 0 + n = n := by simp_arith

    10.7 综合策略选择指南

    面对一个证明目标时，以下决策流程有助于快速选择策略：

    • 目标是多项式等式？ → 先试 ring，如有分母先 field_simp
    • 目标是具体数字的命题？ → norm_num
    • 目标是线性整数/自然数？ → omega
    • 目标是线性实数不等式？ → linarith，需要非线性则 nlinarith [sq_nonneg ...]
    • 目标是正性/非负性？ → positivity
    • 目标含有未知名字的引理？ → exact? 或 apply?
    • 目标涉及 cast？ → norm_cast 或 exact_mod_cast
    • 目标是可判定的有限命题？ → decide 或 native_decide
    • 目标可以用 simp 化简但需要精确控制？ → simp only [...]
    -- 综合例子：证明对所有整数 n，有 (2n+1)² ≡ 1 (mod 8)
theorem odd_sq_mod8 (n : ℤ) : (2*n + 1)^2 % 8 = 1 := by
  have expand : (2*n + 1)^2 = 4*n^2 + 4*n + 1 := by ring  -- ring 处理展开
  rw [expand]
  have factored : 4*n^2 + 4*n = 4 * (n^2 + n) := by ring  -- ring 处理因式
  rw [factored]
  have two_dvd : 2 ∣ n^2 + n := by
    have : n^2 + n = n * (n + 1) := by ring
    rw [this]
    rcases Int.even_or_odd n with ⟨k, hk⟩ | ⟨k, hk⟩
    · exact ⟨k * (n + 1), by rw [hk]; ring⟩
    · exact ⟨n * (k + 1), by rw [hk]; ring⟩
  obtain ⟨m, hm⟩ := two_dvd
  rw [hm]
  ring_nf
  omega  -- 最终线性算术
