    Setting Up a Training Environment on a Server

    ← Learning

    Compiled from hands-on experience setting up QLoRA + GRPO training at Chaitin Tech. Every pitfall described here cost several hours to work through.

    1. First Steps After Getting a Server

    Start by checking the basics:

    nvidia-smi          # GPU model, memory, and driver version
nvcc --version      # CUDA version (install separately if missing)
cat /etc/os-release # operating system version
python3 --version   # system Python version

    The CUDA driver and CUDA toolkit are two different things. The upper-right corner of nvidia-smi shows the highest CUDA version the driver supports; nvcc --version shows the installed toolkit version. PyTorch depends on the toolkit, so use the nvcc version to choose the right PyTorch wheel.

    2. Miniconda Installation and Environment Management

    Do not install packages into the system Python — it pollutes the global environment and is hard to clean up later. After installing Miniconda, use a separate conda environment for each project.

    wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc

# create a new environment
conda create -n train python=3.10
conda activate train

    Specify the Python version when creating an environment. Different training frameworks have different Python version requirements; verify them beforehand.

    3. Installing PyTorch (Matching Versions Is Critical)

    The PyTorch website has a command generator: enter your CUDA version and OS and it produces the exact pip/conda command. Follow it strictly. Running pip install torch without a version flag installs the CPU-only build.

    # example: CUDA 12.1
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

# verify GPU is available
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"

    If torch.cuda.is_available() returns False, first check whether the PyTorch and CUDA versions match, then check whether the driver is functioning (nvidia-smi should run without errors).

    4. tmux: The Most Important Tool

    When an SSH connection drops, any running training process gets killed. tmux keeps your session alive after disconnecting.

    tmux new -s train      # create a named session
tmux ls                # list all sessions
tmux attach -t train   # reattach to a session

# inside tmux:
Ctrl+b, d              # detach; the session keeps running in the background
Ctrl+b, c              # open a new window
Ctrl+b, <number>       # switch to window <number>

    Always start a tmux session before launching a training run — this is a non-negotiable habit.

    5. GPU Monitoring

    nvidia-smi                    # one-shot snapshot
watch -n 1 nvidia-smi         # refresh every second
nvtop                         # interactive display (install separately)

    Once training starts, keep watch -n 1 nvidia-smi running in a separate tmux window to monitor memory usage in real time. Slowly increasing memory usage indicates a leak that will eventually cause an OOM crash.

    6. Common Causes of OOM and How to Handle Them

    OOM (Out of Memory) is the most common error in training: CUDA out of memory. Ordered from most to least likely:

    • batch_size too large: the most common cause. Halve it first and see if training starts.
    • Sequence length too long: attention memory scales as the square of sequence length. Reduce max_length.
    • Gradients not cleared: confirm that optimizer.zero_grad() is called every step.
    • Memory fragmentation: adding torch.cuda.empty_cache() before training can help, but does not solve the root cause.
    • Model itself too large: consider QLoRA (quantization + LoRA), which can reduce memory requirements to roughly one-quarter.

    When reducing batch_size, use gradient accumulation to compensate: effective_batch_size = batch_size × gradient_accumulation_steps.

    7. Experiment Tracking (Wandb)

    Training logs printed only to the terminal are hard to analyze after the fact. Wandb automatically records loss curves, learning rate, GPU utilization, and more, and produces shareable visualizations.

    pip install wandb
wandb login       # enter your API key (register at wandb.ai)

# in your training script:
import wandb
wandb.init(project="my-project", name="run-1")
wandb.log({"loss": loss.item(), "lr": scheduler.get_last_lr()[0]})

    If the server has no internet access, use wandb offline mode to log locally and sync later.

    8. A Common Pitfall: Mixing pip and conda

    pip can be used inside a conda environment, but mixing pip and conda sometimes causes dependency conflicts, especially for CUDA-related packages. Rule of thumb: install PyTorch via the official pip wheel, install other packages with pip, and avoid using conda install for scientific packages since the conda channel versions often lag behind.
