    在服务器上搭建训练环境

    ← Learning

    整理自在成亭科技做 QLoRA + GRPO 训练时的实际经验。每个坑基本都是用几个小时换来的。

    一、拿到服务器后的第一步

    先确认基本信息：

    nvidia-smi          # GPU 型号、显存、驱动版本
nvcc --version      # CUDA 版本（没有就需要单独装）
cat /etc/os-release # 操作系统版本
python3 --version   # 自带 Python 版本

    CUDA 驱动和 CUDA toolkit 是两回事。nvidia-smi 右上角显示的是驱动支持的最高 CUDA 版本，nvcc --version 是已安装的 toolkit 版本。PyTorch 依赖 toolkit，所以以 nvcc 的版本为准来选 PyTorch wheel。

    二、Miniconda 安装与环境管理

    不要用系统自带的 Python 装包，会污染全局环境，将来很难清理。Miniconda 安装后每个项目用独立的 conda 环境。

    wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc

# 新建环境
conda create -n train python=3.10
conda activate train

    创建环境时指定 Python 版本。不同的训练框架对 Python 版本有要求，提前确认。

    三、安装 PyTorch（版本对应很关键）

    PyTorch 官网有一个安装命令生成器，输入你的 CUDA 版本和 OS，它会给出对应的 pip/conda 命令。严格按照这个来，不要直接 pip install torch——默认会装 CPU 版本。

    # 示例：CUDA 12.1
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

# 验证 GPU 可用
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"

    如果 torch.cuda.is_available() 返回 False，先检查 PyTorch 和 CUDA 版本是否匹配，再检查驱动是否正常（nvidia-smi 能否正常运行）。

    四、tmux：最重要的工具

    SSH 连接一旦断开，正在跑的训练进程就会被 kill。tmux 让你的会话在断开后继续运行。

    tmux new -s train      # 新建会话，命名为 train
tmux ls                # 列出所有会话
tmux attach -t train   # 重新连接到会话

# 在 tmux 内部：
Ctrl+b, d              # 脱离（detach），会话继续后台运行
Ctrl+b, c              # 新建窗口
Ctrl+b, 数字键         # 切换窗口

    每次开始训练前都应该先开一个 tmux 会话，这是最基本的习惯。

    五、GPU 监控

    nvidia-smi                    # 一次性查看
watch -n 1 nvidia-smi         # 每秒刷新，观察训练过程中的显存占用
nvtop                         # 更直观的动态界面（需要单独安装）

    训练开始后，watch -n 1 nvidia-smi 挂在另一个 tmux 窗口里，可以实时看到显存是否撑得住。如果显存占用缓慢上升（内存泄漏），最终会 OOM 崩溃。

    六、OOM 的常见原因与处理

    OOM（Out of Memory）是训练时最常见的报错：CUDA out of memory。按可能性从高到低排列：

    • batch_size 太大：最常见原因。先减半，看是否能跑起来。
    • 序列长度太长：attention 的显存占用是序列长度的平方。将 max_length 减小。
    • 没有清理梯度：确认每个 step 都调用了 optimizer.zero_grad()。
    • 显存碎片化：训练前可以加 torch.cuda.empty_cache()，但不能解决根本问题。
    • 模型本身太大：考虑 QLoRA（量化 + LoRA），可以把显存需求压缩到原来的 1/4 左右。

    调整 batch_size 时可以用 gradient accumulation 补偿：effective_batch_size = batch_size × gradient_accumulation_steps。

    七、实验追踪（Wandb）

    训练日志只打印到终端，跑完之后很难回头分析。Wandb 可以自动记录 loss 曲线、学习率、GPU 使用率等，并生成可分享的可视化界面。

    pip install wandb
wandb login       # 输入 API key（在 wandb.ai 注册后获取）

# 在训练脚本里加：
import wandb
wandb.init(project="my-project", name="run-1")
wandb.log({"loss": loss.item(), "lr": scheduler.get_last_lr()[0]})

    如果服务器没有外网，用 wandb offline 模式先本地记录，回来再同步。

    八、一个常见的坑：pip 和 conda 混用

    conda 环境里能用 pip 安装包，但 pip 和 conda 混用有时会造成依赖冲突，尤其是 CUDA 相关的包。经验法则：PyTorch 用 pip 官方 wheel 安装，其他包用 pip 安装，尽量不用 conda install 装科学计算包（因为 conda 源里的版本往往落后）。
