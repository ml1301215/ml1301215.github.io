    Lean 4 入门路径：从竞赛数学到 Mathlib 形式化

    以下是我在形式化 18 道 ICCM 竞赛题过程中总结的路径，面向有数学背景但没有类型论经验的读者。参考了 Lean 4 入门教程（依赖类型论基础）及 Mathlib4 文档。

    环境搭建：安装 elan（Lean 版本管理器），用 lake new myproject math 创建带 Mathlib 依赖的项目，首次 lake update 会拉取预编译缓存（约 1–2 GB）。推荐 VS Code + lean4 插件，右侧面板实时显示证明目标状态（Infoview）。

    核心概念：Lean 4 中的定理证明是构造一个具有给定类型的项（Curry-Howard 同构）。theorem 关键字声明命题类型，by 进入 tactic 模式，每条 tactic 缩减证明目标，直至所有目标被关闭。

    常用 tactics 速查（竞赛数学场景）：

    -- 自动化算术
ring          -- 环等式，处理多项式恒等式（最常用）
norm_num      -- 具体数值计算（验证 2^10 = 1024 之类）
omega         -- 整数 / 自然数线性算术，竞赛题必备
linarith      -- 线性不等式推导（支持假设的线性组合）
nlinarith     -- 非线性不等式（可加平方项作 hint：nlinarith [sq_nonneg x]）

-- Mathlib 搜索
exact?        -- 搜索能直接 close 当前目标的引理
apply?        -- 搜索能 apply 到当前目标的引理
simp?         -- 列出 simp 调用了哪些引理（调试用）

-- 逻辑变换
push_neg      -- 将否定推入量词（¬∀ x, P x → ∃ x, ¬P x）
contrapose    -- 转换为逆否命题
by_contra h   -- 引入反证假设 h : ¬Goal

-- 结构拆解
intro h       -- 引入全称量词 / 蕴含前件
obtain ⟨a, b⟩ := h  -- 析构存在量词或合取
cases h       -- 按构造子分情况讨论
rcases h with ⟨a, b, hb⟩  -- 嵌套析构

    Mathlib 命名惯例：引理名按"结论结构"命名，下划线分隔。Nat.add_comm 是自然数加法交换律，Int.mul_comm 是整数乘法交换律，Nat.lt_of_add_lt_add_left 表示"去掉左边加数后保持严格小于"。不等式引理常以 _le_、_lt_ 为中缀；存在性引理常以 _exists_ 或 Exists. 开头。不确定时，用 exact? 或 Mathlib 在线文档搜索。

    竞赛题形式化的标准工作流：

    1. 写 statement：把题目翻译成 Lean 的 theorem 类型签名，用 sorry 占位通过编译，确认类型正确。
    2. 在纸上把证明写清楚，找到每一步对应的 Lean 概念（等式 / 不等式 / 存在性 / 归纳 / 构造性）。
    3. 用 have h1 : ... := by ... 逐步替换 sorry，用 exact?/apply? 找到 Mathlib 引理名。
    4. lake build 验证整个文件无 sorry 且编译通过。

    常见坑：

    • ℕ 和 ℤ 之间的转换（Int.ofNat、Nat.cast）：纸面上的"正整数"在 Lean 里必须想清楚用哪个类型，跨类型运算需要显式转换。
    • omega 只处理线性整数算术，含乘法的目标需要 nlinarith 或手动分解。
    • Mathlib 版本更新可能改变引理名；用 exact? 动态查找而不是硬编码引理名，避免升级后编译失败。
    • 证明目标中的 ⊢ 符号表示"待证明"；case 关键字处理多目标分支时需要显式命名。

    大模型微调笔记：QLoRA + GRPO 实战

    以下是在成亭科技实习时，对 Qwen3-30B-A3B 进行安全告警分类微调的经验整理。参考了 TRL GRPOTrainer 文档、unsloth 以及实际 A100 双卡环境下的 OOM 调试经历。

    为什么选 QLoRA：30B 参数模型全量微调需要数十张 A100。QLoRA 通过 4-bit 量化冻结基座模型，仅训练低秩适配器（LoRA），将单卡显存需求压缩到可接受范围。核心代价是训练速度略慢，以及量化引入的轻微精度损失——对领域适配任务通常可接受。

    LoRA 配置要点：

    from peft import LoraConfig

lora_config = LoraConfig(
    r=8,               # 秩：越大表达能力越强，显存也越大；8 是常用起点
    lora_alpha=16,     # 缩放因子，通常设为 2*r
    target_modules=[   # 注入 LoRA 的目标层（注意力 + FFN）
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

    为什么选 GRPO 而不是 SFT：SFT 只优化"复现正确答案的格式"，但安全告警分类的核心困难是非对称损失——漏报严重告警的代价远高于误报。GRPO（Group Relative Policy Optimization）通过 reward 函数直接编码这种不对称性，让模型在训练过程中真正优化业务目标，而不是拟合标注分布。相比 PPO，GRPO 去掉了 critic 网络，内存开销更小，收敛也更稳定。

    Reward 函数设计（非对称惩罚）：

    def security_reward(completions: list, labels: list) -> list:
    rewards = []
    for pred, label in zip(completions, labels):
        pred_class = parse_class(pred)   # 从生成文本中提取分类结果
        if pred_class == label:
            rewards.append(1.0)          # 正确分类
        elif label == "critical" and pred_class != "critical":
            rewards.append(-3.0)         # 漏报严重告警：重罚
        elif label != "critical" and pred_class == "critical":
            rewards.append(-0.5)         # 误报严重告警：轻罚
        else:
            rewards.append(-0.3)         # 其他错误
    return rewards

    训练加速：使用 unsloth 对 QLoRA 训练加速（利用手写 CUDA kernel 和 Flash Attention 2，官方称约 2× 速度提升）。显存进一步优化：调低 gpu_memory_utilization（推荐 0.2–0.4），启用梯度检查点（gradient_checkpointing=True），per_device_train_batch_size 从 4 降到 2 可显著降低 OOM 风险。

    核心结论：用对称 reward（最大化整体精度）训练的模型，在严重告警的召回率上比非对称 reward 训练的模型低约 15 个百分点。基座模型选择（同量级）对这个指标的影响远小于 reward 设计。对于任何奖励信号不对称的分类任务，reward 函数的设计是最值得投入时间的地方。

    正特征代数几何笔记（手稿）

    特征 p 下的代数几何在细节处与特征 0 有根本不同。Frobenius 态射的存在改变了向量丛的稳定性理论；quasi-elliptic fibration 的出现（仅在特征 2 和 3 中）使得标准的 Bogomolov 不等式证明失效——经典证明依赖 Frobenius 下半稳定性的保持，而这一性质在准椭圆情形中不成立。
