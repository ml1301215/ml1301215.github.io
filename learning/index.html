    学习历程

    我的学习轨迹大致可以分为三个阶段，每个阶段的核心问题不同，但方法论是一贯的：先建立框架，再做精确的事情。

    数学基础：从竞赛到代数几何

    本科之前的竞赛经历（CMO 一等奖）给了我一种思维习惯：解题不是靠灵感，而是靠分类。对新题型建立可复用的框架，比单纯积累题量更有价值。这套习惯在后来学习代数几何时被直接复用——面对一个新概念，先问"它是哪类对象"，再问"它在哪些变换下保持稳定"。

    研究生阶段的工作集中在正特征代数几何。Frobenius 态射的存在让特征 0 中许多显然的结果在正特征中失效，而 quasi-elliptic surface 恰好是那种只在特征 2 和 3 中才能存在的对象——它的存在本身就是正特征几何的产物。研究 Bogomolov 不等式向这类曲面的推广，迫使我理解 Frobenius 与向量丛稳定性的精细相互作用。结果收录于 Journal of Mathematics, 2025。

    编程与系统：从 C 语言到 AI 工程

    研究生期间系统学习了编程栈：C/C++ → 数据结构与算法 → Linux 系统编程 → MySQL / Redis → Docker → Git。目标不是掌握每个工具的全部细节，而是建立足够的心智模型，能在需要时快速定位"这个问题在哪一层解决"。学习过程中的笔记习惯延续了竞赛时期的做法：写下来是为了在写的过程中发现理解的漏洞，而不只是备忘。

    算法方面花了约 8 个月、2000 道题建立系统化框架。对我而言，从数学竞赛向算法竞赛迁移的关键不是技术，而是认识到：题型归纳的思维是相通的，不同的只是具体的工具集（双指针、滑窗、动态规划，对应数学中的归纳、构造、反证）。

    AI 工程：从 API 到微调到多智能体

    进入 AI 工程领域的入口是 Vibe Proving——我想让 LLM 证明数学题，但立即发现"让模型生成文本"和"让模型做可验证的事情"是完全不同的问题。这个认识驱动了后续所有工作的选题逻辑。

    在京东实习期间（2025 年夏）接触了 RAG 和多智能体系统架构。在成亭科技（2025 年秋）做了第一个认真的微调项目：QLoRA 压缩 30B 参数模型，GRPO 对齐分类行为。这两段经历让我理解了"用 AI 解决问题"和"认真对待部署约束的 AI 工程"之间的距离。2025 年底在腾讯云黑客松（AI 渗透测试赛道）拿到第一名，是对这段学习的一个小结。

    目前在中关村 AI 研究院做研究实习，专注 AI for math 方向。核心问题还是那个：LLM 如何做真正可验证的推理？
