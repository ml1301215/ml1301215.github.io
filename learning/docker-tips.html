    Docker 使用注意事项

    ← Learning

    整理自在京东和成亭两段实习中使用 Docker 部署服务和训练任务时积累的经验教训。Docker 的概念本身不复杂，难的是使用过程中的细节。

    一、镜像与容器的区别（常见误解）

    镜像（image）是静态的模板，容器（container）是运行中的实例。一个镜像可以启动多个容器。

    最常见的误解：在容器里改了文件，以为下次启动时还在。实际上，容器的文件系统是独立于镜像的可写层，容器被删除后这层就消失了。如果需要持久化数据，必须用 volume 或 bind mount。

    二、镜像分层与构建缓存

    Dockerfile 里的每条指令（RUN、COPY、ADD）都会生成一个新的镜像层。构建时，如果某一层的内容没有变化，Docker 会复用缓存，跳过该层及之后所有层的重新执行——前提是该层之前的所有层都命中了缓存。

    这意味着指令顺序很重要。变化频率低的指令放前面，变化频率高的放后面，这样才能最大化缓存利用率。

    # 低效：每次改代码都要重新安装依赖
FROM python:3.10
COPY . /app
RUN pip install -r /app/requirements.txt

# 高效：先复制依赖文件，再复制代码
FROM python:3.10
COPY requirements.txt /app/requirements.txt
RUN pip install -r /app/requirements.txt
COPY . /app

    第二种写法，只要 requirements.txt 没变，pip install 那层就会命中缓存，节省大量时间。

    三、数据持久化：volumes vs bind mounts

    两种方式都可以把宿主机的数据挂载到容器里，区别在于管理方式：

    • bind mount：把宿主机的某个具体路径挂载到容器里。直观，适合开发阶段（代码改动实时同步）。
      docker run -v /host/path:/container/path ...
    • volume：由 Docker 管理的独立存储区域，不依赖宿主机的目录结构。适合生产环境和数据持久化。
      docker run -v my-volume:/container/path ...

    训练任务中，模型权重和数据集建议用 bind mount 挂进去，这样容器跑完删掉，数据还在宿主机上。

    四、不以 root 运行

    默认情况下容器内的进程以 root 身份运行。如果容器被攻击，root 权限可能被利用来逃逸到宿主机。即使是内部使用的服务，也建议在 Dockerfile 里创建非 root 用户：

    RUN useradd -m appuser
USER appuser

    这在有对外暴露接口的服务中尤其重要。

    五、secrets 不要写入镜像层

    Dockerfile 里的每一层都是永久存储的，即使后面用 RUN rm 删掉了文件，那个文件在之前的层里依然存在，docker history 可以看到。

    # 错误：API key 被写入镜像层
ENV API_KEY=my-secret-key

# 正确：运行时通过环境变量传入
docker run -e API_KEY=my-secret-key ...

    对于需要在构建阶段使用 secret 的情况（比如 pip install 私有包），用 Docker Buildkit 的 --secret 参数，secret 不会进入镜像层。

    六、镜像过大的处理

    镜像过大（常见原因：apt-get install 没清缓存、pip 缓存、临时文件）会导致拉取慢、存储占用多。

    # 清理 apt 缓存（放在同一个 RUN 指令里，才不会保留在中间层）
RUN apt-get update && apt-get install -y git curl \
    && rm -rf /var/lib/apt/lists/*

# 清理 pip 缓存
RUN pip install --no-cache-dir -r requirements.txt

    另一个方案是多阶段构建（multi-stage build）：用一个大镜像做编译，只把编译结果复制到最终的小镜像里。对纯 Python 项目不常用，但对有 C 扩展或二进制编译的项目效果显著。

    七、GPU 训练时的额外配置

    容器默认看不到 GPU，需要安装 nvidia-container-toolkit 并在运行时加参数：

    # 安装 nvidia-container-toolkit（宿主机一次性操作）
# 参考：https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html

# 运行时挂载所有 GPU
docker run --gpus all ...

# 只挂载第 0 块 GPU
docker run --gpus '"device=0"' ...

    在容器内用 nvidia-smi 验证 GPU 是否可见。

    八、常用命令速查

    docker ps -a                    # 列出所有容器（包括停止的）
docker images                   # 列出本地镜像
docker rm $(docker ps -aq)      # 删除所有停止的容器
docker rmi $(docker images -q)  # 删除所有镜像（谨慎）
docker logs -f container_id     # 实时查看容器日志
docker exec -it container_id bash  # 进入运行中的容器
docker build -t my-image:v1 .   # 构建镜像
docker system prune             # 清理未使用的镜像、容器、网络
